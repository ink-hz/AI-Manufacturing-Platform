# 制造系统资料与权限对接邮件

**主题：关于制造系统现状梳理、资料交接及访问权限对接的工作安排**

**收件范围：直属主管、IT 负责人、相关系统业务及技术负责人**

## 邮件正文

各位：

为推进后续制造系统的统筹管理及大制造平台建设，近期需要对现有制造相关系统开展统一梳理，形成系统能力、业务流程、数据归属、集成关系及建设需求的完整清单。

目前大制造平台已完成主要业务流程的软件实现。下一阶段需要结合现有 SAP、MES、WMS、PDM、产品测试平台及 BI 等系统的实际情况，明确已有能力的复用方式、跨系统衔接问题和需要补充的业务能力，据此确定平台建设范围和实施顺序。

本次工作重点包括：

1. 梳理各系统的实际功能、使用范围、业务流程及责任分工。
2. 核实订单、工程版本、物料、工单、SN、测试、质量和交付等核心数据的来源及关联关系。
3. 评估现有接口、数据质量、开发扩展和集成条件，明确后续接入方案。
4. 建立制造系统资料、业务负责人及技术对接人的统一清单。

请 IT 负责人牵头组织，各系统业务及技术负责人按下附清单提供现有资料，并落实相应访问权限。资料范围同时覆盖业务侧和开发侧，包括系统使用及管理手册、技术架构、数据字典、接口文档、鉴权授权说明、开发扩展资料及联调样例。

权限范围包括业务查询及必要的数据导出、技术资料访问、测试环境操作、API 调用及必要的日志查询权限。业务页面账号和 API 调用身份分别落实，明确各环境可调用的接口、读写操作、组织及数据范围。具体账号、角色和调用身份由各系统负责人结合职责确认，按现有流程办理。

请各系统同时明确一名业务负责人和一名技术对接人，反馈资料提供及权限开通的预计时间。现有资料可先行提供；缺失资料、暂不具备的权限或接口条件，请列明现状、责任人和后续安排。

资料及权限就绪后，我会组织相关负责人逐系统核对，并选取实际业务样本走查完整制造链路，形成现状评估、问题清单及后续建设安排。

请各位按上述范围安排对接。

## 附件一：系统范围、重点资料及用途

| 系统 | 业务资料范围 | 开发及集成重点资料 | 用途 |
| --- | --- | --- | --- |
| SAP／MRP | 在用模块、业务流程、主数据、订单、工单、采购、库存及计划 | 对应版本的系统手册、相关对象及字段定义、标准及现有定制接口、单据状态和过账回执、接口调用权限及测试环境 | 明确经营计划与制造执行的衔接、数据归属和过账边界 |
| MES／SFC | 工艺路线、过站、防错、用料、质量隔离、SN 及组件追溯 | 使用及配置手册、工单／SN／过站／装配关系的数据模型、设备及产测接口、报工和追溯接口、扩展点及联调环境 | 核实已有执行能力、实际覆盖范围及可复用部分 |
| WMS | 收发存、库位、批次、物料状态、预留及客供料 | 状态及库存口径、收发料和预留接口、扫码及标签规范、与 SAP／MES 的字段映射和回执、接口权限及测试环境 | 梳理从到货、检验到齐套、投产的实际链路 |
| PDM／PLM | BOM、图纸、版本发布、ECR／ECN、与 SAP 及 MES 的衔接 | 版本及生效规则、BOM／文件／变更对象定义、查询下载及发布通知接口、开发扩展文档和接口授权范围 | 明确工程版本如何发布、传递并应用到制造现场 |
| 产品测试／标定平台 | 工站、测试程序、规范、限值、原始曲线及标定参数 | 现有程序及脚本清单、可提供的代码或扩展接口、设备协议及 SDK、数据格式和单位、程序／算法版本、参数写入与回读接口、仿真或测试条件 | 核实测试数据采集、判定、追溯和标定能力 |
| BI | 报表目录、指标定义、数据来源、加工逻辑及刷新机制 | 数据模型、取数视图及加工脚本、数据加工任务和调度、报表或数据接口、开发手册及数据集访问权限 | 统一制造指标口径，复用现有报表和数据 |
| OA | 制造相关审批流程、表单、角色及审批结果 | 流程配置及开发手册、表单字段及流程状态、发起／查询／回调接口、审批身份及附件访问规则、测试流程 | 梳理工程、质量及业务批准如何进入执行环节 |
| CRM、供应商协同及相关客户／海外系统 | 与制造有关的订单、交期、供料及发运 | 相关对象及编码映射、接口或文件交换规范、认证授权、回调及增量同步规则、样例报文和双方技术联系人 | 梳理制造链路的上下游输入与输出 |

系统具体产品、模块和实际启用情况，以此次盘点为准。质量、设备等能力如已包含在 MES 等系统中，按实际模块提供资料；HR 侧先关注制造人员的岗位、资质等关联数据。尚未上线或不适用的系统、模块，请注明现状。

## 附件二：各系统统一资料交付维度

| 维度 | 交付内容 | 主要用途 |
| --- | --- | --- |
| 基本情况 | 产品名称、版本、供应商、业务负责人、技术负责人、运维方及厂商技术支持联系人 | 建立系统与责任人清单 |
| 实际覆盖 | 已启用功能、使用部门、产品线、工厂／产线，以及已知问题 | 核实实际使用范围和能力边界 |
| 系统手册与业务流程 | 当前版本的用户操作手册、管理员及配置手册、业务流程图、角色权限矩阵和关键控制点 | 理解现场作业、系统配置和业务控制规则 |
| 技术架构与部署 | 架构及部署拓扑、环境清单、相关组件及集成平台、系统入口和服务地址、网络接入方式、发布及变更流程 | 确定开发、测试和生产各环境的接入路径及依赖 |
| 数据模型与字典 | 核心业务对象、表／视图或接口对象说明、字段类型、必填及枚举、主键与关联键、编码规则、计量单位、时间及状态／版本规则 | 准确映射订单、物料、BOM、工单、批次、SN 等对象，明确数据归属 |
| 接口目录与文档 | 已有及可开放接口清单、所属系统及版本、调用方向、协议及地址、请求／响应字段、错误码、分页、查询及导出限制、附件或原始文件读取方式 | 形成可实施的接口清单，明确调用条件及返回结果的业务含义 |
| 接口鉴权与授权 | 支持的认证方式、技术账号或应用注册流程、令牌获取及续期、接口权限及数据范围、有效期、白名单和限流要求 | 落实 API 调用身份及授权，核实系统账号与接口账号的对应关系 |
| 同步与一致性规则 | 全量／增量方式、变更或回调机制、删除／撤销规则、顺序与版本、重试去重、幂等、超时后的结果查询、业务成功回执、对账和补偿方式 | 明确跨系统数据同步及业务执行结果，避免重复操作和状态不一致 |
| 开发与二次扩展 | 开发者手册、SDK、扩展点、插件及自定义字段机制、现有定制功能清单、可提供的定制代码及配置、版本兼容要求、许可及厂商支持边界 | 评估在现有系统内扩展或通过外围系统集成的可行性 |
| 联调环境与样例 | 测试环境入口、版本及配置差异、测试账号、接口请求／响应样例、调用示例或接口测试集合、测试数据准备和重置方式 | 使开发人员能够复现调用，验证正常及异常流程 |
| 日志与排障 | 接口及同步任务日志、请求关联标识、审计记录、监控入口、常见故障处理方式和技术支持渠道 | 定位调用失败、数据延迟及业务执行异常 |
| 实际业务样本 | 能贯穿订单、工单、物料、SN、测试、放行和发运的一组实际业务记录，包含跨系统关联编号及代表性异常记录 | 走查端到端制造链路，核实数据关联及流程断点 |

资料优先采用现行有效版本，并注明适用范围、维护负责人及更新时间。实际样本应明确来源系统和关联编号；涉及多个系统时，提供能够相互核对的记录。

接口形态以系统实际支持的方式为准，可包括 API、消息或事件、受控数据库视图及文件交换。通过视图或文件提供数据的，需明确可用对象、字段、访问或交付方式、更新频率和数据口径。标准产品资料与公司现有定制部分的资料分别提供，并标明与当前部署版本的对应关系。

涉及开发扩展许可、接口调用收费或必须由原厂实施的事项，请说明现有合同覆盖范围、办理条件及技术支持安排。

## 附件三：访问权限范围

| 权限类别 | 申请范围 | 用途 |
| --- | --- | --- |
| 业务系统查询及导出 | 制造相关模块、业务对象、明细记录及必要报表的查询和导出权限 | 核实实际业务流程、数据状态和跨系统关联 |
| 资料库及开发资源访问 | 系统手册、流程、数据字典、接口及开发文档、SDK、受控工程资料，以及可开放的定制代码和配置的查阅及必要下载权限 | 梳理系统能力、业务规则及开发条件 |
| 测试环境操作 | 相关测试环境账号，以及覆盖拟验证流程的操作、配置或扩展权限；明确允许验证的业务范围 | 验证业务流程、状态流转、异常处理及扩展方案 |
| 测试环境 API 调用 | 技术账号或应用身份、调用地址、鉴权配置、接口权限列表、数据范围，以及联调所需的读写操作权限 | 开展接口开发，验证字段映射、鉴权、回执、幂等及重试行为 |
| 生产环境 API 查询 | 按已确认的制造业务范围开通查询及必要导出接口，明确应用身份、接口列表、组织及数据范围、限流和有效期 | 核实实际生产数据及接口可用性，为试点接入提供依据 |
| 数据通道访问 | 采用数据视图、消息或文件交换时，开通对应的视图读取、消息订阅或文件目录访问权限，并提供相关对象清单 | 按系统实际支持的方式接入数据 |
| 网络接入 | 相应环境的网络接入、VPN 或网关访问及必要白名单配置 | 建立开发联调及数据查询的实际连接 |
| 日志及运行信息查询 | 接口请求、同步任务、消息处理、审计及相关运行状态的查询权限 | 定位接入问题，核对调用结果与数据同步情况 |

各系统应明确权限适用的环境、角色、模块、组织及数据范围，注明有效期和审批／办理负责人。生产环境的写入、配置及管理权限，结合后续确认的系统职责、管理范围和具体工作另行落实。

账号和应用凭据通过现有受控渠道交付；邮件及对接清单记录身份名称、权限范围、办理状态和责任人。

## 附件四：资料与权限交付反馈要求

各系统按以下字段反馈，形成统一对接台账：

| 字段 | 反馈要求 |
| --- | --- |
| 系统及适用范围 | 系统名称、版本、涉及模块和组织／工厂范围 |
| 对接人员 | 业务负责人、技术负责人及必要的厂商联系人 |
| 资料交付 | 文档清单、版本、存放位置及访问方式 |
| 环境及连接条件 | 测试／生产环境入口、网络开通及白名单状态 |
| 账号与接口授权 | 业务账号及角色、API 应用或技术身份、接口清单、操作及数据范围、有效期 |
| 联调条件 | 测试数据、调用样例、日志入口和支持安排 |
| 缺项及限制 | 当前未提供的资料或能力、原因、责任人和补齐安排 |
| 预计完成时间 | 分别反馈资料提供、账号开通、API 授权及联调环境就绪时间 |
