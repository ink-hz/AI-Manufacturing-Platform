# 制造全流程 mock 验收矩阵

日期：2026-10-28。状态：**测试设计，以下场景全部未执行，不是通过报告**。

关联[产品补充设计](../superpowers/specs/2026-10-28-manufacturing-full-workflow-design.md)。四组主剧本和 32 组专项场景共 36 组；一组可产生多个自动化断言，但报告以业务场景结果为主，不用断言数量代替完整验收。

## 1. 数据与执行方式

- 独立数据库、独立 mock 系统状态和测试身份；每轮记录运行 ID、代码提交、数据种子版本、业务时钟与期望结果。
- 输入保留来源、版本、单位、数量、角色与范围；所有业务动作调用真实平台 API，通过真实授权/参数校验/状态机持久化。mock 只位于外部身份测试提供方或业务系统适配边界，逐项注明。
- 主剧本从需求开始顺序执行至反馈结案，首错即停并保留现场；专项场景分别从声明的前置快照开始，失败不污染其他案例。
- 修复后按影响范围复跑，保留原失败与修复后的两份证据，不修改原始用例以降低标准。
- 页面组件使用相同 DTO 和动作契约；浏览器视觉与人工多角色操作另列未执行/用户验收，不借 API 通过声称页面视觉通过。

## 2. 四组贯穿 S1—S9 的主剧本

| ID | 隔离模拟业务 | 固定数据及正常路径 | 全程断言 |
| --- | --- | --- | --- |
| F01 | 自研相机成熟产品 | 正式订单 100 台；工单 60+40；两个工单各用固定工程修订；料齐、首件、执行、测试与放行；分两批 60+40 发运签收验收；成本结案回执及质量关闭 | 原承诺不被计划覆盖；总分配/合格/发运/验收量可核对；发 60 后剩余 40，整行不关闭；每台履历可查 |
| F02 | 数采相机导入试产 | 需求 20 台，试产工单 5 台及后续 15 台；旧版保留；试产问题、工程修订、评审与重新准备通过后下达后续范围；测试、放行、交付、复盘 | 新版不覆盖旧版 5 台履历；批准/首件/校准证据匹配实际工单；试产问题关闭与后续放行分开 |
| F03 | 3D 打印机 | 订单 10 台，工单 6+4；维护不同于相机的工艺/测试规范；生产和质量记录、两批交付、验收与结案 | 共用模型支持各自路线；项目/订单/工单之间关联明确；相机资料不自动成为打印机已确认条件 |
| F04 | 外部 OEM 机器人 | 订单 30 台，客户版 C1/厂内版 M1；自购与客供分责；客户批准、客供齐套、执行、测试；制造/质量/客户放行；10+20 分批发运、验收及客供对账 | 客户/厂内版独立；客供所有权不混；各方批准独立；合同必需确认缺失时对应动作不可完成；交付和质量/成本关闭分开 |

每组均需留一条已完成但未作废的追溯链：需求/订单行 → 工单 → 工程快照 → 物料批次/SN → 执行 → 首测/复测 → 放行 → 发运/验收 → 反馈。真实成本结账由 ERP 模拟回执表达，不在平台生成会计凭证。

## 3. 专项场景

| ID | 前置与操作 | 必须看到的结果 |
| --- | --- | --- |
| E01 | 询价/预测未批准即申请投产；再录正式订单及来源关系 | 未授权动作拒绝；保留不同承诺状态；同一外部订单导入不重复创建 |
| E02 | 已有分配/采购/在制时改期、减量或取消 | 原承诺保留；变更影响可查，未经处置不静默释放/关闭既有义务 |
| E03 | OEM 客户批准未知、收到错误修订；再补正确回执 | 对应准备/放行保持未满足；错误回执与修正均留痕，其他方通过不能代替客户批准 |
| E04 | 工程新版生效，仍存在旧料及旧工单在制 | 新旧范围可重现；旧工单快照不变；受影响对象的处置未完成时变更不关闭 |
| E05 | 订单需 100 件，合格可用 80，采购在途 20 | 仍缺 20；在途承诺可见，但不得作为已合格齐套依据 |
| E06 | E05 的 20 件实收，IQC 15 合格/5 不合格，后续补齐 5 合格 | 收货、合格、不合格数量分别保存；先缺 5，后变齐套；不良原记录不被补料覆盖 |
| E07 | 尝试使用他客户客供、冻结、过期或已分配给别单的库存 | 可用/分配校验拒绝；保留所有权、状态、批次、单位与占用依据 |
| E08 | 同一供料多次部分到货、供应商改承诺、客户补客供 | 累计与余额正确；原承诺及各次确认保留；自购/客供不重复计入 |
| E09 | 交换单位不匹配、缺单位换算、截点过期或数量精度错误 | 拒绝或保持待核实，不显示已齐套；明确错误字段与来源 |
| E10 | 两张工单申请占用同一可用物料余额 | mock 权威端原子处理、不超额预留；平台保存独立确认回执，待确认请求不计已占用；冲突可定位，重试不重复占用 |
| E11 | 工单下达后改变当前资料版本或尝试直接换绑定 | 执行仍指向原快照；变更走明确修订/切换及重新核对，不能静默替换 |
| E12 | 计划使用日超出治具/设备校准有效期 | 必需准备项不能通过；更新证据并重新核对后才可提交下一动作 |
| E13 | 首件仅“已安排”或检验失败时申请批量开工 | 合法首件试做通道可用，批量动作仍受阻；失败和处置保留，复做通过后才允许相应批量范围 |
| E14 | 错工序、错程序版本、未知 SN、重复过站或超范围报工 | 根据来源契约拒绝/挂异常；不污染已确认数量和履历 |
| E15 | 执行缺料停工，补料/重新确认计划后恢复 | 缺料回 S3/S4，记录发生/响应/恢复时间；不通过改阶段状态抹掉中断 |
| E16 | 100 台中首次通过 96，4 台返工后通过 3、报废 1 | 首次 96 与最终 99 可区分；原始 4 次失败和报废保留；发运 100 被拒绝 |
| E17 | 测试记录缺实测值/单位/限值版本或版本与执行依据不符 | 保持不完整/异常；PASS 文本不能代替完整测试与符合性证据 |
| E18 | 生产角色提交质量放行；再由有资格质量角色操作 | 越权动作拒绝且无业务成功记录；合法主体及其依据可审计 |
| E19 | 制造方和质量已放行，合同要求的客户放行仍未知 | 仍不满足发运条件；三个决定分别可查，客户确认后才允许提交发运 |
| E20 | 从坏料批次正查；从出货 SN 反查；对关联范围申请冻结 | 正向定位受影响产品/客户，反向关联物料/版本/测试；冻结提交与权威系统确认分开，未确认时显示待处理 |
| E21 | 合格并已放行 100，发运 60；再试重复发同一 SN、超发 41，最后合法发 40 | 余额 40、重复/超发被拒绝；第二批完成后再按验收条件关闭履约 |
| E22 | 已发运但未签收；已签收但未完成约定验收；验收有遗留项 | 发运/签收/验收各自独立，必需遗留项有负责人，不能自动完成交付 |
| E23 | 收到 ERP 成本结案，仍有未解决质量问题/客诉 | 财务来源结案可见，质量仍未关闭；单一“项目完成”不吞掉遗留项 |
| E24 | 已交付 SN 发生 RMA，检测、围堵、根因、纠正、效果验证并触发 ECO | 全链关联；失败与退货保留；CAPA 有效果验证，后续变更需有执行/切换证据 |
| E25 | 同业务标识重复提交，再以同标识改内容 | 相同输入返回同一结果，不重复写入；不同内容明确冲突，原记录不覆盖 |
| E26 | mock 外部已处理但响应超时；恢复后查询回执 | 显示结果待确认，先查后决定后续动作；同一业务只执行一次 |
| E27 | 冻结/解冻或版本更新乱序到达 | 旧事件不覆盖新状态；业务序号/源版本与拒绝原因可追溯 |
| E28 | 对账出现明细差异但合计相同，或模拟接口明确拒绝 | 差异不被合计掩盖；生成可处理异常；拒绝不显示已过账 |
| E29 | 无登录、无资格、跨项目或跨客户读取/修改；旧授权失效后重试 | 服务端按范围和动作拒绝；无数据泄露或业务写入；旧页面/回调退役 |
| E30 | 两人同时编辑和提交；失败时跳到手册、返回或离开 | CAS 冲突保留草稿；手册全文及上下文保留；放弃后执行一次离开动作，无二次确认 |
| E31 | 关键阶段重启服务后重新登录读取、继续动作和核对仪表盘 | 对象、历史、数量与来源不丢；多个页面聚合同一业务事实，重复继续不重复落单 |
| E32 | 运行不同测试种子、复位演示、修改 mock 外部状态后重跑 | 测试可复现；只复位本轮隔离数据；生产数据与既有演示记录不受影响，界面持续标明模拟来源 |

## 4. 每组结果必须保存的证据

运行 ID、源提交与构建版本、种子/场景版本、角色与授权范围、业务唯一标识、输入和数据截点、期望与实际结果、相关接口状态、持久化对象及事件摘要、外部模拟回执、失败现场、重启后读回结果、耗时。

结论分为通过、失败、阻塞、未执行。mock 组件/API 全流程、真实系统接口、用户浏览器实操、生产验收与业务改善分别报告。所有 F01—F04 和 E01—E32 是目标验收范围；它们当前均为“未执行”。
