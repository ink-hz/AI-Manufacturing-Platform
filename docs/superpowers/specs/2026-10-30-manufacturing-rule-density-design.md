# 制造工作台规则信息精简设计

日期：2026-10-30。用户确认：线上制造工作台常驻的规则说明过多，希望业务操作更聚焦。本文只改变信息呈现，不改变制造事实、权限、阻断判定、业务命令或持久化。

## 目标与原则

用户进入工作台时先看当前业务对象、状态、阻断原因和能做的动作。系统仍必须明确区分隔离模拟、人工登记、接口采集、未知结果和权威已接受；这些标识及真实错误、拒绝、截断提醒不得因为精简而消失。审计与排障所需的来源、版本、回执和历史保留在原数据路径中，并可在页面按需展开。

## 页面设计

1. **首页和台账。** 删除不影响操作的重复规则长句；保留数据范围不完整、读取失败、阻断和只读提示。业务台账的来源列缩为“来源系统 + 登记方式”，不常驻展示业务编号和来源版本；对象标题仍可进入详情。项目内列表同样使用简短来源。工作台顶部保留数据集名称及“生产/隔离演示/隔离测试”模式，去掉重复的“人工登记保留来源凭据”。
2. **对象详情。** 状态和阻断原因保持在首屏。记录版本、来源字段、回执和输入版本等解释性信息放入有明确标题的原生 `details` 折叠区。来源折叠区标题需显示“人工登记/模拟系统/接口采集”等关键来源类型，避免折叠后误认模拟为真实。准备检查项、数量、当前资格和失败原因仍常驻；通用规则解释移入“操作说明”或删除重复句。
3. **规则分析。** 默认只显示“查看核对建议”入口，不自动请求分析；展开后才按当前项目和分析范围读取。收起时终止未完成读取，切换项目后不显示旧项目结果。分析标题、建议、阻断和未知信息可见，详细来源、原始证据、相似记录、测量表和 8D 草稿放在建议项内部。错误与截断警告在展开状态保持可见。
4. **工作区说明。** 工程导入、测试标定、供料、执行、质量、同步回执等页面的静态规则段落收为统一的“操作说明”；正在阻断、待停机、未接入等会改变当前决策的提示保持常驻。

## 边界

不修改后端 API、schema、审计数据、权限、表单必填字段或提交路径。不用 CSS 隐藏整块业务信息；折叠控件可用键盘打开，标题说明内容性质。保留手册全文和所有业务记录。页面文案不宣称规则分析是模型 AI，也不宣称人工登记已完成设备或外部系统动作。

## 验收

前端组件测试检查：默认没有规则分析请求，展开后读取且项目切换不复用旧数据；简短台账保留来源模式和阻断；详情默认收起完整来源并能展开；阻断、失败、模拟与未知提示仍可见。TypeScript 构建和相关前端回归通过。按用户和平台既定要求，不由 Agent 操作浏览器做页面验收。若上线，遵循现有制造发布流程，从准确主线提交构建候选并记录实际版本。
