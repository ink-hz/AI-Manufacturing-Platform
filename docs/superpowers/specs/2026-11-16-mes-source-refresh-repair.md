# MES工单页读取失败修复

本次为已批准真实MES工作台的缺陷修复，保持原只读、授权和完整性契约。用户实际页面显示通用失败，云端同范围两次并发工单读取均成功，已有成功缓存且错误为空。现有后端并发用例证明：旧请求完成时会返回较新snapshot及`MES_REFRESH_SUPERSEDED`，GET缓存则返回真实持久化结果。页面当前将所有refresh_error映射为连接/权限/组件上限错误。

1. 保留后端序列检查，旧请求不得覆盖新缓存。前端收到`MES_REFRESH_SUPERSEDED`后，仅追加一次相同范围的缓存GET，按其真实snapshot/error展示；不得再发源POST、轮询或隐藏源失败。若缓存尚无结果，明确提示其他查询正在更新，可人工刷新。
2. 这次缓存GET也应用账号、API、来源、对象和卸载隔离；保留旧成功结果和原采集时间。真实失败按已知安全code显示对应业务原因，禁止直接呈现未经筛选的message、异常或接口细节。
3. “全流程模拟环境·隔离演示数据”来自正式台账dataset，不能盖在真实MES源工作台上。源工作台使用其已核实来源标签；正式台账仍按实际dataset显示演示/测试/生产身份，不把demo全局改成production，也不修改线上dataset或业务记录。
4. 无新增依赖、不变更源/Mac/PF接口、不改变权限，不扩大本轮到跨系统工单映射。页面源码/组件和隔离真实HTTP验收由开发负责；员工登录和浏览器仍用户验收。

验证先复现现行通用失败，再验证一次缓存GET、无额外源POST、真实错误保留、异步隔离和正式台账标签。生产MES/WMS及SAP/MRP业务写入持续为0。
