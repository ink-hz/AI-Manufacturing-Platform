# M2：引用观察与已准入对象办理物料任务

日期：2026-11-12。承接用户已确认的[评审顺序](../../reviews/2026-11-12-robot-oem-review-response-confirmation.md)及本轮“开始呗”的实施指令。T2来源契约已交付，本设计将[T3任务书的M2](../../taskbooks/robot-oem/03-iqc-receipt-and-results.md)展开为实施边界；生产源仍遵守[AGENTS.md](../../../AGENTS.md)只读规则。

## 1. 用户完成什么

- 仓库只看到包裹、位置和标签时，MC可直接派“核实物料”任务，不先造需求、供应承诺或正式收货。
- 只有已保存的MES工单组件、还没有平台需求/收货时，也能指派人核实到料、身份或位置。组件不称为到货。
- 收货对象已经准入并保存时，直接引用它安排IQC，服务器带出准确收货及需求；用户不重新填写一遍原账。
- 指定人员在现有“事项”或项目物料任务中接手、反馈和记录核实结论。核实完成不自动增加合格量、分配量或线边实收。

采用扩展现有`material_tasks`的方案，共用接手、转交、历史和权限。另建核实工单系统会增加入口与重复状态；继续强制本地正式收货则保留原问题。页面沿现有料况与任务详情就地办理。

## 2. 当前可用依据和明确边界

| 依据 | 本轮可办理 | 保留限制 |
| --- | --- | --- |
| `arrival`人工到场观察 | 无需求/无收货时派核实任务 | 包裹数不是物料数量，无批次/单位不形成IQC依据 |
| MES持久组件快照 | 按工单、绑定、快照和组件行派核实任务 | 需求/已提料不代表实际收货、位置或检验 |
| 已有平台收货 | 复用既有IQC任务、当前有效检验核对 | 人工例外记录持续标识，不升级为原生来源 |
| 已准入源收货投影 | 用准确源键解析既有收货后安排IQC | 当前集成事实是明确mock；原生生产收货/IQC采集仍需可信契约 |

本轮不猜测MES检验报告与收货行/批次/单位的关系，不新增原生采集器，不用mock补成生产准入。T3跨无关需求共享检验仍需明确分配/关联证据；本轮只复用已有可证明的同一收货范围，及兼容历史需求的关联。

## 3. 引用输入、固定证据与去重

`material_task.open`保留现有receipt/handoff参数，增加可选的严格类型`reference`：

| kind | 输入身份 | 服务端核对 |
| --- | --- | --- |
| arrival | id、version | 当前项目观察、匹配历史版本 |
| mes_component | binding_id、snapshot_id、component_key | 快照→绑定→当前项目工单；新建使用有效绑定最新快照 |
| receipt | id | 当前项目已有准确收货、承诺、需求、批次和单位 |
| source_receipt | source_key | 已接受投影的完整源键/版本、原事实哈希、项目及准确收货目标 |

客户端只选择身份，不提交可信来源、环境、数量或任意URL。引用与legacy receipt/handoff字段同时提交时拒绝歧义；旧参数继续可用。

任务的manual source用于协同记录归责；`reference`证据由服务端生成，分别保留项目、来源类型、方式、环境、原对象/版本、读取/发生时间，以及工单/绑定/快照/组件或收货/批次/单位。数量需要展示时复用T2投影；不复制原始报文、凭据或连接配置。未知环境保留unknown，集成模拟保留mock。

活跃任务去重采用稳定范围，而非快照版本或物料名称：到场观察按观察ID；MES组件按环境命名空间、绑定和组件键；IQC按实际收货ID；追查保持原交接范围。刷新快照不新增同范围在办任务，替换绑定不暗改旧任务。同一范围已在办时打开/返回原任务，不改原责任人；新的兼容需求关联追加留痕。

新增`material_task_requirements`保存已核对的上下文关联，迁移保留原主需求。核实关联仅表示“请核对该需求”，不分配数量；IQC关联仍严格验证现有lineage/工单/物料/货主/单位/精度。不因物料同号关联无关需求，移除某项需求不自动取消其他关联任务。本轮不增加无依据的跨工单共享规则或自动改写主需求。

## 4. 核实任务生命周期与结论

新增`task_kind=verify`，`requirement_id`可空。IQC可由准确收货推导主需求；trace仍要求原需求和交接。复用`pending→processing→closed/cancelled`，进展可有预计时间和受阻说明。

协调角色继续负责发起、转交和撤销。核实可指派给当前项目有效的供料、项目负责人、仓库、生产或质量成员；核实资格不授予检验权限，IQC仍需质量角色及inspection资格。每次操作重查当前授权、只读、目录有效性和实际责任人，转交由新责任人接手后生效。

核实完成使用现有close命令，但必须选择适用结论并填写依据：

| 结论 | 适用含义 |
| --- | --- |
| identity_verified | 核实了所引用的观察/对象身份；服务器复核该依据当前有效 |
| unable_to_verify | 已核实仍无法查明，说明障碍；物料问题继续存在 |
| incorrect_observation | 观察或原关联有误，保留原因与历史 |
| superseded | 本次核实范围已被替代，保留依据 |

这些结论不借用IQC/寻料的数量完成条件。核实拒绝补收handoff证据、找到数量和检验数量字段；不提供多余的强制“待审核”步骤。旧IQC/trace的close结论与正式数量校验保持原义。

初始引用证据固定保存。任务详情另外显示当前引用和陈旧原因；来源改变时不静默覆盖初始证据。identity_verified若遇旧快照/匹配版本，需要操作者明确采用同一稳定范围的当前`resolved_reference`；保存初始与完成两份证据。跨绑定替换不能这样移花接木，可有原因结束旧任务。到场观察只在当前实际匹配收货一致时，才能用该收货作为核实结果；MES组件不按同物料自动关联收货。

核实引用本身不证明收货/检验。已有准确收货时，有权协调人在详情直接安排IQC；无准确收货时显示具体缺项，保留核实结论，不造正式账。IQC合格12/待检8仍保留8待检；合格12/拒收8可完成本次已检范围，补料问题继续存在。

## 5. 引用选择与现有页面

新增只读分页`GET /projects/{project_id}/material-task-references`，支持引用类型、工单、需求上下文、准确收货ID筛选和业务搜索；已知收货使用有界精确查询，不受其他收货的分页位置限制；先按授权/类型/筛选再分页，返回总数、项目版本和可直接提交的引用。列表有业务名称、来源/环境/时点及已有任务；不让用户输入内部UUID或源键。

到场观察尚无工单身份时，作为项目观察明确显示待关联，不伪装属于所选工单。MES组件按工单准确筛选。收货仅返回项目内确有依据的对象；源收货未准入时不显示可安排IQC的假条目。

在料况页增加就地“安排核实”入口，即使需求表为空也可用；MES组件行可带入准确引用，原无到货提示改为可办理的核实/例外观察入口。有实际新包裹需记录时提供简洁的到场观察表单，元数据自动归责；已存在观察不重复录入。原IQC/查料表单和旧深链接继续使用。

任务详情增加引用与核实结论，共用现有项目任务列表及事项入口。查询、草稿、保存回执均绑定项目/用户/API/引用/操作代次；切页、更新、撤权及保存期间导航不串写、不清掉新草稿。M6每项目50条事项截断仍是独立后续任务，本轮不声称已修复。

### 读取刷新与草稿所有权

复审发现同一类草稿丢失来自共同原因：可刷新的详情/当前匹配读模型同时决定了有状态表单是否挂载。项目版本ACK使读模型暂时失效时，卸载会绕过表单内部的代次保护。

表单所有权按API、用户、项目、任务及用户明确选定的收货建立；同一所有者的版本刷新只更新读取新鲜度，不卸载或清空草稿。读取期间隐藏旧的当前依据、禁用相关提交；当前收货变化时保留原草稿与目标，要求明确重新选择，不能悄悄改派到新收货。真正切换所有者继续使用已有离开确认/隔离机制。详情刷新也遵循这一规则，不能通过清空父详情间接卸载子表单。验收用实际WorkflowApp覆盖嵌套IQC的延迟ACK与新草稿、同收货刷新、改关联及撤权。

## 6. 持久化与宿主

数据库v27→v28：扩展task_kind、允许无主需求的verify、保存引用与稳定键，增加上下文需求关联。迁移保留任务ID/seq、状态、原始payload/source、closure、历史、补收证据及sqlite_sequence高水位。父子表在同一FK开启的事务内重建，先复制替代表、后删旧子表/父表、重命名并恢复索引，foreign_key_check通过后才推进版本；失败回滚。不在事务内关闭FK，不重写旧证据伪造来源。

新路由需在现有PF宿主精确GET允许清单中接入，保持项目授权、管理只读、旧制造模块不可用行为；不开放任意路径/URL，也不增加源系统写入。两个仓库分别提交、审查和本地主线整合；发布与生产数据库迁移不在本轮执行。

## 7. 验收

1. 空需求项目：已有到场观察→分派核实→本人接手→反馈→有据结论，库存/质量/收货/承诺/预留/交接/外部源事实不变。
2. 只有MES快照：从组件派核实，不建平台需求；重放复用，刷新/替换绑定及旧响应正确区分；陈旧依据不得静默核实完成。
3. 准确源收货：直接选择已有准入投影安排IQC，无手工重录；来源mock保持标识，同范围重复不换责任人；未准入/外项目/错批次单位不准创建。
4. 旧IQC、trace、历史任务及补收组迁移后可读可办；12合格/8待检不能完成，12合格/8拒收可完成检验但不能消补料；找到2不冒充实收。
5. 51+引用及跨项目尾页、源别名/版本、撤权、目录失效、CAS/幂等、重启、迁移回滚、连续草稿与保存期间导航均有自动化证据。
6. 新宿主GET路由的受权/拒绝/旧版不可用、实际回环HTTP及完整岗位页面流程分别验证。使用隔离项目、FakeMes和明确模拟集成事实；原生生产同单及浏览器/现场验收分别保留。
