# SAP MRP真实契约mock设计

日期：2026-11-12。状态：承接用户“按测试环境真实接口、自己mock数据”“开始吧”的开发授权，补充实现规范；**功能尚未实现**。归属[T1工单与需求](../../taskbooks/robot-oem/01-mes-order-and-demand.md)扩展，落实产品评审M4/M5。MRP是SAP内能力，本轮只观察供需清单，不运行MRP。

**2026-11-13决定更新**：用户已改为按当前权限直接接入真实SAP测试环境，缺权再说明。真实接入以[新设计](2026-11-13-sap-real-test-read-design.md)为准；本文mock实施保留为历史方案，不作为当前开发前置或失败回退。本文数量来源、环境隔离及观察不等于正式分配的约束继续适用。

## 1. 用户得到什么

在隔离OEM项目的料况需求中，计划/MC可查看对应物料＋工厂的SAP供需观察，对照现货、供应、需求和日期，验证缺料与急料办理。页面持续标明“模拟SAP”；已核实物料/工厂由上下文带入，映射缺失时给出具体待核实项。

日常入口仍是项目料况和事项。场景选择在隔离联调管理区；不要求MC操作接口路径、SOAP或内部ID。模拟用于开发和岗位走查，不产生生产齐套、预留、质量放行、源发料或过账结论。

## 2. 实现选择和边界

采用**契约层模拟**：合成SOAP响应经过现有请求构造、WSDL解析和`parse_response`；只替换传输端。不直接手写一份业务页成功JSON，也不把既有`core_sap`业务模拟器改称真实BAPI。

| 选择 | 取舍 |
| --- | --- |
| 契约层模拟，本设计采用 | 可发现字段/结构不匹配，切换真实读取时复用解析和投影；需准备脱敏契约fixture |
| 页面直接使用JSON假数据 | 开发较快，绕过真实接口契约，不能满足本轮目标 |
| 立即搭建独立SAP模拟服务器 | 增加部署、权限与路由维护；本轮进程内传输替身已足够 |

默认关闭mock。仅受信服务配置显式启用，限定隔离项目；普通请求不能传任意源地址、切换生产连接或以参数自选mock。源读取失败不静默退到mock。未来接入生产SAP仍须独立验证并维持只读，不放宽现有传输环境/函数限制。

## 3. 唯一已核实的接口契约

复用`src/manufacturing_platform/sap_access/`：

- 函数：`BAPI_MATERIAL_STOCK_REQ_LIST`；查询维度是物料＋工厂，不是工单查询。
- 请求由`stock_requirements.envelope(material, plant)`构造；`MATERIAL`最多18字符、`PLANT`最多4字符，沿用现有校验。`GET_ITEM_DETAILS=X`，其他指示开关和表输入沿用现有固定值。
- 响应结构、命名空间、SOAP action、所有行字段和RETURN/MRP_LIST字段以真实测试WSDL为准，走`contracts.parse_wsdl`和`stock_requirements.parse_response(payload, contract)`；不拿精简假WSDL代替真实类型表。
- 保留源数量为十进制字符串、原日期与单位。日期含义或MRP元素码语义未核实就展示原义/待核实，不从字段名推断通用净需求算法。
- 沿用最大50条明细和响应字节上限；51条不能截成50条并声称完整。当前接口没有经核实的分页契约，不发明下一页参数。空结果与超限分别处理。
- `RETURN.TYPE`为E/A/X保持`SAP_BUSINESS_FAILURE`；超时、非法结构、未知场景、契约不匹配分别失败，不改成空列表或成功。

脱敏fixture从现有受控测试WSDL导出，移除端点、账号和真实业务标识，保留字段、类型、长度、精度、响应结构与SOAP action。保存来源说明、原件摘要、脱敏件摘要及结构核对结果；合成响应只使用自建物料/单据。fixture不得包含凭据或真实业务响应。

## 4. M4前置：每个数量携带可追溯身份

在现有`SourceRef`、原生绑定与读取版本之上增加料况数量投影，不破坏历史事实。至少包含：

| 字段 | 约束 |
| --- | --- |
| `value`, `unit`, `meaning` | 十进制字符串或null；单位与数量含义明确。未知用null；需求、现货、合格、预留、已提料、线边实收分别命名 |
| `origins` | `native` / `manual` / `file` / `mock` / `unknown`的去重集合；单一事实只有一个值，派生值取全部输入的并集，不由前端根据标题猜测 |
| `fact_role` | `confirmed` / `observation` / `unknown`，表示平台确认或观察等用途；平台确认的模拟数据仍在`origins`中保留`mock` |
| `environments` | `production` / `test` / `development` / `mock` / `unknown`的去重集合，派生值保留全部输入环境；与来源方式、事实角色分开 |
| `source_refs` | 来源系统、环境命名空间、对象类型与外部ID、版本/快照、经核实的项目/物料/工厂关联。原有内部引用可复用，不新增公开凭据 |
| `observed_at`, `collected_at`, `coverage` | 发生/读取时点；完整、部分、失败或未知。派生数值不以页面刷新时间冒充源事实更新时间 |
| `input_refs` | 派生值可追到全部输入和其数量语义；合并相同来源引用，不省略mock或未知输入 |

派生判断继承所有输入的限制。任一模拟输入使结果持续标为模拟；任一未知/不完整的必要输入使对应结论待核实；跨环境不得形成正式生产数量。历史记录缺少环境不自动补成生产。物料＋工厂供需清单只能说明该查询范围，不证明某工单已分配。

标识在服务层生成并参与准入和查询隔离；列表、详情与证据展开共用同一投影。`source_modes`页级汇总可保留，不能替代逐项身份。不得改写原有SourceRef把模拟伪装成api，也不批量给历史人工记录补“原生”身份。

## 5. 七个可重复场景

使用固定合成物料/工厂和受控时钟，每个场景保存预期请求、合法响应或确定的失败类型。下列是业务样本设定，不把观察样本推广为通用MRP算法。

| 场景 | 合成事实与页面预期 | 禁止推出的结论 |
| --- | --- | --- |
| 现货足够 | 查询范围需求20、现货20、单位一致；显示现货与需求对照 | 不代表已归属本工单、质量合格或已到线 |
| 缺料 | 需求20、现货12、无其他可核实供应；显示样本差额8及采购/协调入口 | 不覆盖平台独立确认的预留口径，不重复扣减 |
| 迟到 | 需求时间明确，供应20的可用日期晚于需要时间；显示具体日期风险 | 未核实日期含义或无需要时间不判“不急” |
| 部分到货 | 需求20、现货12、剩余供应8；显示12和8分别所属阶段 | MRP清单本身不证明正式收货批次或IQC完成，不自动生成收货/IQC |
| 空结果 | 合法SOAP、0明细，保留查询物料/工厂、时间和mock身份 | 不判定无需求、全部齐套或连接失败 |
| 业务拒绝 | 合法RETURN E/A/X，返回既有业务错误并保留可重试上下文 | 不变成成功0条、不写入新有效快照 |
| 超时 | 传输替身抛出确定超时，走既有失败/审计路径 | 不sleep等待、不读真实SAP、不自动退回成功场景 |

另测非法物料/工厂、字段遗漏/增加、非法结构、超过50行/字节上限、单位/身份不匹配、旧响应以及撤权。场景目录选择错误应显式拒绝，不选默认成功。失败保留上次完整版本及其旧时间、场景和来源，界面可区分本次失败与旧事实。

## 6. 业务集成与替换真实来源

1. T2先交数量来源契约和未知/模拟隔离。
2. T1实现独立mock传输及场景fixture，使用同一BAPI解析链；mock服务身份明确，不复用`source=native_sap`冒充真实读取。
3. T1把物料＋工厂观察接入隔离项目需求的只读对照；绑定须有明确依据。MES工单组件仅作独立观察，未经核实不按同号或同物料自动合成联合需求。
4. 隔离业务场景中，已有MockAuthorityAdapter可提供单独明确的模拟预留/检验事实；来源不可被SAP清单隐式写入或覆盖。生产项目不准准入这些模拟事实。
5. 宿主复用当前认证/项目授权与精确路由允许清单。任何新增路由均须在制造模块和宿主分别校验权限及旧版本不可用行为，不开放任意代理路径。
6. 获得后续真实SAP环境后，使用相同契约与投影读取；来源命名空间独立，旧mock历史保留原身份，不原地改为真实记录。另做权限、精度、上限/性能、字段版本和真实同单映射验收。

本轮不新增MRP执行、计划发布、检验提交、收发料、调拨、过账、打印或生产源签收。平台本地协同声明沿现有权限继续；根目录[AGENTS.md](../../../AGENTS.md)对生产源只读的规则持续有效。

## 7. 独立验收与开发归属

- 契约测试：七场景经过真实类型fixture和共用解析器；请求固定、字段完整、数字精度不丢失、所有失败不伪装成功，且无网络调用。
- 项目API：显式mock隔离项目可读；普通生产项目、跨项目、撤权、只读命令及未知来源被准确处理；模拟不能进入正式生产满足量。
- 页面：料况中看见模拟身份、物料/工厂、供需、日期、覆盖及失败；常规岗位不进入技术配置，保持原需求上下文。
- 宿主：使用现有实际宿主做受权回环HTTP验证，禁用/旧版模块返回预期不可用，不绕过精确路由授权。
- 旅程：在隔离项目串接急料、IQC待办及实收声明，数量来源一路保留；合格12/待检8不关闭剩余8，实收18/20不因找到2结束。现场岗位走查另留证。

开发文件归属：契约/传输在`src/manufacturing_platform/sap_access/`独立模块；业务观察投影在`src/manufacturing_platform/workflow/`；来源和对照界面在`webui/src/workflow/materialControl/`；对应`tests/sap_access/`、`tests/workflow/`和页面测试。宿主接入在其制造模块和精确路径允许清单中完成。进入实现前按本spec展开TDD实施计划，不能把本文勾成“mock已完成”。
