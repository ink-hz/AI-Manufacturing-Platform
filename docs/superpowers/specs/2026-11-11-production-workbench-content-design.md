# 产测工作台：内容与任务路径收敛

用户已授权全部重构；本轮依据其真实页面反馈继续执行。现有页面把 API 的读取范围、来源证明和空状态当成主体，再叠加尚未开始的调查，用户无法辨认下一步。根因是页面按数据读取过程组织，而非按使用任务组织。修复职责由页面展示与导航承担，源接口、调查持久化和权限保持原契约。

## 使用顺序

管理员首先判断所选时段哪些项目有测试、哪些项目涉及失败。首屏保留平台的一个“产测管理”标题、三项任务导航、紧凑的项目与时间工具栏、四个关键数字及项目表。数字为“有测试项目、测试次数、测试 SN、失败 SN”；SN 为来源、项目内去重，不宣称产品数量或最终不良。

项目表展示项目、测试次数、测试 SN、失败 SN、失败次数、最近测试、操作。点击“查看失败”进入该项目失败分析，项目名称可进入项目详情。完整统计确认为零的项目折叠为“本时段无测试的项目（数量）”，展开只显示项目及可用的最近测试时间、查看入口。统计不完整或不可用的项目必须留在主表并明确未知，不得归为零。

“运行总览、失败分析、上位机活动”分别承担总览、失败定位、上位机测试活动任务。内部 anomalies 标识保持不变。后两项未选择项目时显示相应任务的项目选择列表；选择项目仍留在当前任务。它们不能显示同名运行总览假装切换成功。

## 信息层级

删除重复标题、阶段式口号、成功读取证明、重复时间范围说明、空调查表单和扫描实现说明。完整读取时不显示 Coverage 段落；每块数据至多显示一次简短更新时间。统计口径和来源时间放在按需展开的“统计说明”。真实失败、部分读取、旧数据和图表展示截断仍直接提示，采用简短的任务语言。

时间工具栏只展示实际查询的项目、开始和结束时间及应用/刷新操作。输入值必须精确表达查询秒数/毫秒，禁止只显示分钟却保留隐藏秒数。固定时间与自动重新读取不矛盾；删除“已暂停自动更新”之类无法反映真实状态的说明。恢复、捕获、交接的范围不可被舍入或重写。

趋势图中测试次数与其中失败使用同一个数量尺度，保留精确十进制数及原始区间下钻。缺失时间格保持未知，筛选范围内的记录不可称为“含所有结果”。首页不再放置逐项目小趋势图。

## 调查逐步出现

初始总览不展示调查表单。用户点击开始/恢复调查、选中调查对象，或存在真实调查/恢复错误/冲突时才展示相应内容；根控制器始终挂载，保留自动保存、脏状态、CAS 冲突、固定交接及事件/日志绑定。恢复入口必须先展开再聚焦。由链接恢复失败也必须可见，不能把错误藏掉。当前调查隐藏时必须提供明确的继续入口，不能丢失或静默覆盖。

## 验收与边界

- 仅改前端；不新增依赖，不改源查询、21 条路由、首期管理员权限、后端、持久化格式或发布工具。
- 不改其他制造模块的标题和工具栏；不引入浏览器验收流程，浏览器验收仍由用户完成。
- 使用匿名合成项目做组件验证，不把用户贴出的真实项目和数据写入测试。
- 组件验证首次屏幕内容、折叠零项目、保留未知项目、任务导航、秒数显示、恢复入口及原调查保护行为；图表验证共同尺度、精确计数和范围下钻。
- 已授权上线；验证及独立评审通过后归并主线，使用既有完整候选与仅 API 切换流程发布，保留并避开用户并行 SAP 工作。
