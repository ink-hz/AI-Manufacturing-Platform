# 产测管理：四条工作路径

用户已确认上一轮产品方案并要求开始开发，补充硬性要求：页面不能堆放时间解释、数据口径和开发信息。此规格记录已确认的实现范围；沿用现有只读源接口及首期管理员资格。版本提测/准出写入、实际岗位权限开放、测试项判定聚合和预期版本生效基线不在本轮；不得做成虚假的已可用操作。

## 页面与用户旅程

主导航为「项目总览、失败分析、现场上位机、版本使用」。无项目时，后三项呈现对应项目选择入口；选择后保留任务与准确时间。已知SN/记录查询、工具目录和调查恢复是快捷入口。项目总览保留现有紧凑项目表及四指标，不重新放回大卡片或项目趋势墙。

失败分析服务工程师：错误排行→选中症状→上位机/版本组合分布→失败记录→SN前后履历→单次参数和对照。排行改为紧凑列表/表格，每行显示错误、工具/环节、失败SN、失败次数和适用样本，不逐行渲染四指标卡。选中后主区直接给出影响规模、集中条件、失败记录入口；趋势按需展开，不默认占据整页。分布使用紧凑表格，提供限定、进入机器、查看记录等明确操作。使用错误分析现有分母与missing_fields语义，不增加未经验证的测试项排行。原精确查询和调查对象保护必须保留。

现场上位机服务PE：机器名单→具体机器及问题时段→失败与版本组合→测试记录→必要时查看最近30分钟近况。机器名单使用表格列出名称、测试SN、失败SN、测试次数、最近测试及查看操作；活动时间格为辅助内容，不用一排四指标卡作为名单。仅机器详情展示症状、版本及独立近况；不得把无上报称为离线。保留96格边界、未知格、缺失设备条件和夹取下钻。

版本使用服务工具负责人：选择项目→实际工具/配置版本组合→查看组合使用位置→查看该组合全部或失败测试→SN与详情。组合表显示生产阶段、工具及版本、配置名称及版本、测试次数、测试SN、失败SN、最近测试和操作。只读取现有versions/devices分析及有界目录，名称无法取得时显示可理解的缺失名称，不暴露内部字段名。不同阶段、工具、配置身份和缺失值不能合并。大整数保持字符串。所有下钻必须带完整版本组合条件、原项目和精确时段；失败操作另外设置status=2，全部测试不携带旧症状过滤。无数据、部分读取、错误和晚到响应分别处理。不要声称已安装、已部署、违规版本或最终质量结论。

## 内部视图契约

内部 `view=catalog` 继续表示工具与版本模块；本轮其默认展示升级为版本使用，显式 `Location.catalog` 则进入已有工具/配置目录。第四主导航进入catalog并清除目录子选择，工具目录快捷入口显式设catalog=software；事件版本目录链接继续带software_versions/config_versions。不新增持久化view枚举，不改后端协议或调查格式。恢复catalog调查时清除上个页面遗留的目录子选择，按保存的版本范围进入模块默认页；其他视图、捕获、日志及CAS行为保持。浏览历史仍携带具体目录选择。

## 页面语言硬约束

- 页面正文没有读取时间、捕获时间/行号/快照号、源命名空间、指纹、协议、schema、内部字段名、原子快照等开发信息；无「统计说明」或数据口径教学区。
- 业务时间仍出现在范围选择、真实测试/日志事件、图表坐标、近况对照和必要交接有效期；保留实际秒/毫秒，不改写已捕获边界。
- 完整读取不显示成功说明或更新时间。自动刷新是简短操作，不讲轮询周期。部分结果使用「部分结果未显示，请缩小范围」这类短提示，错误使用影响＋可操作的重试，不打印截断码或技术原因。
- 原始业务参数仍可按需展开；它们不是页面开发信息。目录默认只显示名称、版本、说明和有意义的审核状态，取消Object.entries暴露整行后端字段。
- 调查开始/恢复后才呈现；真实保存失败、未保存修改、冲突、内容待核对及不同调查范围必须清楚可操作。保留交接号和版本等用户需要的引用，不把后台定位参数当正文。
- 不增加无数据功能、讲解卡、示例业务数据或占位指标。

## 验收

四个任务入口及项目选择保持任务；版本组合精确过滤、缺失条件、全部/失败/设备下钻可完成；工程师可以从错误到代表事件、SN和对照；PE可从机器到时段和原记录。默认页面及详情不出现过程/技术段落，真实错误和未知仍可见，其他制造模块不受影响。现有源查询、21路由、管理员限制、调查控制器、持久化、依赖和发布工具不变。只用匿名合成夹具；不运行浏览器自动化，由用户验收真实布局和使用。完成审查、主线整合、既有36项目标镜像候选和保全复核后按已有上线授权发布。
