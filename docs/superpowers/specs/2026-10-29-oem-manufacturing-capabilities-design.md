# 制造导入、测试标定与能力复用设计

用户已确认 2026-10-29 对照机器人 OEM 汇报提出的产品与架构修改，并授权开始开发。本规格约束本轮软件开发，不包含排期或业务收益承诺。

## 产品范围

内部自研相机（含数采相机）、3D 打印机与外部 OEM 共用现有订单、版本、物料、工单、质量、交付主线。在同一工作台增加工程导入、测试标定与复用资产，深化物料办理与权威来源展示。项目继续承担责任和授权上下文。

产品入口保留独立制造壳、企业身份、全局管理员完整业务权限和连续 Markdown 手册。新增业务页必须展示可办理对象、真实状态、下一步动作和持久化结果。表单使用业务字段与具名选择，不向用户要求输入 JSON 或后端命令。

## 全局约束

- Python >=3.11；沿用 FastAPI、Pydantic、SQLite、React19、TypeScript、Vite；不新增第三方运行依赖。
- 所有新写动作进入现有 WorkflowService/CommandRegistry；所有新对象进入 ObjectRegistry。沿用实时授权、只读、CSRF、CAS、操作 UUID 幂等、真实操作者审计和 private/no-store。
- 平台所有者与平台管理员默认拥有全部现有及未来项目和全部已注册业务动作；普通成员继续按项目角色、资格隔离。
- 外部 ERP/MRP/MES/WMS 和设备尚未真实接入；界面持续显示人工登记或隔离模拟来源，禁止伪造连接成功、客户批准、测试、标定写入或生产事实。
- 新记录采用增量 schema 迁移；原工单/SN/限值/协议/历史不静默改写；既有未绑定新流程的项目保持原有业务行为。
- 客户专属记录不得因复用而跨项目公开。公共资产只公开审核后的通用内容，源项目与源问题仍按原权限保护。
- 原始 PPT 与现有用户材料保留备份。89项问题明细和40站定义没有提供，不补造为真实数据；所有新增演示样本明确标为模拟。
- 工业设备控制、真实标定算法、真实企业外部系统接入和生产现场验收不由模拟流程冒充。

## 工程导入与复用资产

新增严格对象 `npi`、`npi_issue`、`reusable_asset`、`asset_use`。NPI 绑定同项目已固定工程修订，记录产品族和导入场景（首次导入/变更验证）。资料清单、工程评审结论、实际试产工单/结果和问题均保持版本和来源。

动作：`npi.open`、`npi.review`、`npi.trial`、`npi.issue`、`npi.resolve`、`npi.approve`、`asset.publish`、`asset.apply`、`asset.verify`。

工程评审记录必需检查项、证据、判定（通过/阻断/不适用及原因）。试产绑定同项目同修订工单，不凭勾选生成生产或测试事实。批准必须有通过的评审、实际有效的试产证据、无未解决问题、适用资产检查通过。明确绑定 NPI 的工单批量开工必须核验批准；试产仍走现有试产规则；未绑定历史工单不额外阻断。

问题保存现象、风险、临时措施、已验证原因、对策和验证证据，解决后保留历史。资产从已解决并验证的问题发布，包含标题、类别（检查项/工艺模块/测试模块）、版本、产品族适用条件、执行内容和验证方法。发布即冻结；新版本指向旧版本，旧实例保留原快照。

资产默认项目专属。平台管理员可显式发布通用的整理内容；公共目录只返回通用内容，禁止包含来源问题正文、客户资料或未授权项目关系。应用资产时必须核对适用产品族，形成目标项目独立快照和检查实例；验证必须保存结论和凭据。新资产发布不自动改变旧工单。公共资产通过经授权 API 提供受限查询，不能提供未授权源对象访问能力。

## 测试标定与组件履历

新增严格对象 `test_plan`、`test_run`、`calibration`、`component_link`。测试计划引用同项目工程修订及受控测试规范，记录层级、工位、设备、治具和标定算法版本；发布后的依据不可变。

动作：`test_plan.publish`、`test_run.start`、`test_run.finish`、`calibration.record`、`calibration.confirm`、`component.install`、`component.remove`。

运行状态与判定分离，完成、中断和无效不能互相冒充。运行绑定实际 SN、计划和执行上下文；结束的数值测量必须按现有质量规则验证，合格/不合格测试进入现有质量履历，不能形成平行的放行捷径。已有生产、返工、限值、固件和设备检查条件继续成立。每次尝试独立，结束结果不可覆盖；重复相同命令复用原回执。

原始曲线是有单位、有顺序采样点的受限结构化数据，日志有大小限制，内容摘要与运行绑定；不接受任意服务器路径或任意 URL 充当已获取原始数据。初始实现允许在独立原始数据对象中保存小规模载荷，未来可换存储适配器；不能只用一段文本代表曲线。

标定记录保存实际参数、算法版本、依据运行与验证结果。设备写入确认必须独立记录来源、凭据和匹配的回读参数摘要；未确认不能显示已写入。人工登记和模拟回读持续可辨。测试通过不自动产生质量放行。

厂内SN继续保持现有全局唯一身份；`unit.alias`将客户序列号与既有实物关联，客户编号按客户身份命名空间唯一，不同客户可各用001，历史别名不覆盖。组件安装关联已存在父 SN、物料身份、组件 SN、来源和可选批次；组件身份在项目内明确命名空间，单个有效组件不能同时装到两台机器。拆除关闭关系、保留原段；安装/拆除不删除历史，不改写耗料和库存事实。客户端支持单台档案查看安装与拆换历史。

## 现场到料登记

新增项目责任范围内的`arrival`观察记录，支持已知项目的直发料/包裹先扫码或输入登记，不要求先虚构采购单、物料主数据或合格库存。记录实际到货编号、位置、包裹数量、登记描述和来源；未核对的寄件方/物料信息保持声称。通过`arrival.record`登记，`arrival.match`关联实际同项目收货记录。观察登记和关联都不增加库存、IQC合格量或预留。纠正关联需要明确原因并追加历史，旧关联事实不删除。未知所属项目的全厂包裹不是本轮借用虚假制造项目处理的范围。

## 系统权威与辅助分析

现有架构改为按业务事实、业务范围核实唯一权威。已有 MES/WMS 能承担的事实由其继续承担，平台维护受控适配、来源、回执和对账；统一入口不等于本系统生成全部事实。

新增项目范围权威映射对象与具名动作，记录对象范围、系统、负责人和契约凭据；区分已登记、已核实、实际连接。没有真实适配器验证不允许标记为生产已连接；模拟数据集明确为模拟。配置登记不切换既有在制品来源或绕过当前源导入验证。

辅助分析从当前授权范围内的固定对象生成带引用的建议：导入缺项、物料阻断、变更关联、案例和规范检索、测试结果核对与8D证据草稿。测试只陈述已有测量/运行异常与相似记录，不推定因果或预测；8D仅整理已有问题、登记原因、措施和验证，缺失项明确未知，不编造团队或有效性。规则生成内容明确标识规则分析/草案，不宣称已调用大模型或已验证根因。生成建议不提交业务动作、不改变质量放行；所有后续办理仍走原命令路径。

## 交互与导航

在现有台账之外增加工程与导入、测试与标定入口。复用资产归工程工作区，质量问题可定位关联源。现有项目入口和直接链接在升级时保持可用，项目作为上下文；不能因改导航丢失草稿、筛选或历史入口。

新页面按业务对象组织：选择项目/修订/工单/SN后办理。空态有真实创建入口；状态、错误、只读和冲突可见。原始曲线以数据表和可视图表达，数值、单位与源一致。所有异步读取与提交复用现有身份退役、AbortController、草稿保护和版本刷新机制。

## 验收

采用隔离数据库和实际 HTTP：建立工程修订→导入评审→试产及失败问题→解决验证→发布资产→另一个适用项目采用→检查验证→批准。验证不能跨项目读源、版本冲突、撤权、只读、CSRF和幂等。

采用实际执行与质量依据：发布测试计划→运行→保存曲线和测量→失败/中断不能放行→返工复测→记录标定→匹配回读确认→组件安装拆换可追溯。保留旧36场景及授权回归，补新业务场景。全流程模拟与真实系统验收分别记录。
