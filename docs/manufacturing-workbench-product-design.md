# 大制造工作台产品设计

版本：v0.2。日期：2026-10-27。状态：首版已开发并发布；真实账号页面验收待用户完成。实际版本见 [首版发布记录](release-2026-10-27.md)。

## 产品定位

首版服务制造信息化负责人及获授权参与梳理的人员，帮助他们沿制造流程记录现状、发现问题并跟进待办。

核心使用路径只有一条：**选择内部或外部业务 → 选择业务线 → 选择环节 → 记录现状和待办 → 保存 → 下次继续。**

页面由业务对象和可执行操作组织。行业知识用于解释当前环节，公司现状由使用者记录，两者分开展示。

## 首版范围

保留两个页面：流程总览、环节工作区。采用现有平台的侧栏、字体和页面样式，在「业务工作台」下增加「大制造」。进入后直接显示流程总览。

与其他方案相比，流程图配侧边抽屉能减少页面跳转，但编辑区域较窄；多模块首页可以承载更多工作，却增加首期导航。首版选总览与工作区两个页面，让每次操作集中在一个环节。

产品项目管理、全局系统台账、生产数据看板和 AI 对话留作后续扩展。本版完成记录、保存和继续工作的闭环，并把参与方、交接资料和系统关系关联到具体环节。

## 业务分组与业务线

「内部／外部」表示业务归属：内部是奥比自有业务，外部是客户委托制造，不按销售客户是否在公司外部分类。

```text
内部业务
├── 自研相机（含数采相机）
└── 3D 打印机
外部业务
└── OEM 代工代料
```

机器人是用户此前提到的 OEM 场景，外部业务不限定为机器人。数采相机先归入相机业务线，后续确有独立管理需要时再拆分。

业务分组、业务线名称、排序、启停和所用流程由配置维护，使用稳定标识。改名、排序或移动分组不丢历史记录，停用保留数据；首版不增加配置后台。九环节是默认共用模板，具体工艺、交接规则和以后按需增减的环节由业务线决定。

## 页面一 流程总览

页面顶部提供「内部业务」「外部业务」切换，其下选择业务线，再显示可点击的流程环节。只有一条业务线时显示名称即可。流程采用纵向列表，保持明确的先后阅读顺序，桌面和手机使用同一结构。

```text
大制造

[ 内部业务 ]  外部业务
[ 自研相机 ]  3D 打印机

01  需求确认        未记录         →
02  工程准备        未记录         →
03  计划安排        未记录         →
04  物料与资源      未记录         →
05  工单与开工      未记录         →
06  生产执行        未记录         →
07  测试放行        未记录         →
08  交付验收        未记录         →
09  结案反馈        未记录         →
```

线框表示首次使用的空白状态。记录产生后，每行显示「已记录」和实际未完成待办数；没有待办时省略数量。顶部不增加统计卡片或第二套菜单。

「未记录／已记录」只说明该业务环节有没有已保存的现状内容，不表示生产进度、流程合规或企业正式确认。添加待办不改变这个状态。

各业务线的现状、待办和关联信息独立保存，不自动复制。记录描述该业务线流程的调研现状，适用型号或项目可写入说明；首版尚不管理具体订单。改名不会改变所属记录。

## 页面二 环节工作区

点击环节进入独立工作区。页面固定展示业务归属、业务线与环节名称；返回总览时保留原业务线选择和位置。

```text
← 返回流程
外部业务 / OEM 代工代料 · 物料与资源

确认物料由谁提供，以及人员、设备和工装是否就绪。
了解这一步 ▾

我们现在怎么做                         编辑
尚未记录，先补充已了解的情况。

待办                                  ＋添加
目前没有待办。

协作与数据关系 ▸
```

页面内容分为三部分。

| 部分 | 默认显示 | 具体操作 |
| --- | --- | --- |
| 环节说明 | 一句话说明这一步的目的 | 点击「了解这一步」展开短解释、两三个调研提示及相关来源；可按需进入原始资料 |
| 我们现在怎么做 | 已保存内容，或明确的空白提示 | 点击「编辑」后填写现状，保存或取消；保存后显示更新人和时间 |
| 待办 | 当前环节的简短事项列表 | 输入标题即可添加；可修改、标记完成和重新打开；已完成事项默认折叠 |

现状编辑采用一个文本框，用环节相关的问题引导输入。例如物料环节提示「谁采购、谁供料、谁检查齐套？哪些情况还不清楚？」。填写者可以记录部分事实与待核实事项，无需填完一张长表才能保存。

待办首版只保留标题与完成状态，不强制填写负责人和截止日期。它表示流程梳理中的后续工作；完成待办不会自动确认现状，也不会推动制造工单。

空白待办标题不可提交。现状清空并保存后，总览恢复「未记录」，已有待办继续保留。未保存的现状草稿不会提前改变总览状态。

「了解这一步」初始收起。这里提供经过整理的环节解释和知识出处，首版不将它标为 AI 生成回答。

## 参与方与交接资料

环节底部的「协作与数据关系」默认收起，展开后可编辑参与方、交接资料和关联系统。首页不展示三套信息表。参考分工与使用者保存的实际关系分别标明，未记录不代表没有参与方。

| 场景 | 应能表达的参与方与责任 | 交接重点 |
| --- | --- | --- |
| 自研产品工程准备 | 奥比研发、制造工程、质量 | 工程设计/BOM、制造 BOM、工艺及测试版本 |
| OEM 工程准备 | 委托客户/机器人设计方、奥比工程与制造 | 谁提供设计和 BOM，谁接收评审，谁批准变更与替代 |
| 物料准备 | 奥比采购、物料供应商、仓储与来料质量 | 采购需求、供应商交期、物料批次、到货与检验放行 |
| 生产与交付 | 制造、测试质量、客户或内部接收方 | 工单、实际用料、测试结果、放行与约定验收 |

参与方按「名称、角色、在本环节承担什么责任」登记。同一组织可以承担多个角色。外部参与方记录是业务协作信息，不自动开通外部账号或访问权限。

交接资料按「资料或数据名、提供方、接收方、版本/依据、说明」登记。设计 BOM 和制造 BOM 分别标识，记录转换与确认责任；客户批准、制造方放行和实际投料是不同事实。OEM 代工代料包含加工与物料组织，具体采购范围、特殊客供料及余料处置按实际约定记录。

## 已有系统的分工与对接

| 系统能力 | 在流程中需要对上的数据 | 常见使用环节 |
| --- | --- | --- |
| 设计来源或 PLM | 设计资料、工程 BOM、版本与变更 | 工程准备 |
| ERP | 物料编码、采购、企业库存与业务订单 | 计划、物料、交付与结案 |
| MRP | 需求、BOM、可用供应、缺料与补充建议 | 计划安排与物料准备 |
| MES | 工单执行、工序、实际用料、批次/SN与过程结果 | 工单、生产、测试与追溯 |

该表是参考能力分工，实际产品、模块、字段权威与接口需盘点确认。MRP 可以是 ERP 中的能力，不预设它是一套独立软件，也不把 ERP 与 MES 的同名库存或工单直接当成同一事实。

首版可在环节登记「系统名、类型、相关数据、维护方、交换方式、说明」。交换方式记录人工、文件、API 或待确认；页面明确这是关系登记，尚未验证技术连接。登记 API 不会变成已接通，更不会触发供应商或业务系统调用。

真实对接按「确认厂商及接口 → 确认字段和责任 → 只读接入一个对象 → 以实际回执验证 → 再扩展写操作」推进。首次优先候选为物料、BOM、库存或工单，实际选择取决于用户提供的系统资料与业务目标；缺少产品信息和合法连接配置时不伪造同步结果。首版上线报告分别说明已交付的关系登记与仍待联调的真实接口。

## 一个具体使用例子

以下演示操作，不是已确认的公司事实。

进入「外部业务 → OEM 代工代料 → 物料与资源」，添加待办「确认各类物料的采购范围与供应商交期回传方式」。访谈后记录结论和依据，在协作关系中关联供应商与现有系统，再完成待办。返回总览后，该节点显示「已记录」；刷新或再次登录仍能继续查看。

如果访谈尚无结论，保留待办和不确定说明，不把问题改写成既定规则。

## 保存与使用状态

- 保存期间显示「正在保存」；服务端确认后才显示保存成功和更新时间。
- 读取失败时展示重试入口，保留已读取的内容及其时间，不把失败显示成空白业务。
- 保存失败时保留正在编辑的文本并提示尚未保存，允许重试。
- 离开未保存的编辑时提示保存或放弃；取消编辑恢复已保存内容。
- 多人同时修改时提示内容已更新，保留本地编辑供核对，不静默覆盖。
- 没有阅读权限时显示无权访问；只有阅读权限的用户可以浏览，编辑操作按权限开放。

## 业务数据与平台分工

平台提供企业身份、授权入口和导航，`AI-Manufacturing-Platform` 维护制造业务包与界面。首版业务包由平台进程加载，界面在平台原生壳内挂载，避免新建一套登录和网络身份链；独立版本以只读发布目录提供，业务记录使用独立持久化位置。服务端检查阅读和编辑权限，页面按钮状态与服务端授权保持一致。首发开放平台 owner/admin，普通成员无权；目录硬过期时读取保持、写入禁止。后续按明确人员范围扩展授权。

| 对象 | 首版保存内容 |
| --- | --- |
| 业务目录与流程定义 | 稳定的分组/业务线/环节标识、名称、排序、启停、默认模板、短解释及参考关系 |
| 环节现状与关系 | 业务线、环节、现状、参与方、交接资料、系统关系、更新人和修改版本 |
| 环节待办 | 所属业务线与环节、标题、完成状态及创建和修改信息 |

九环节复用已有[制造流程工作底稿](workflows/manufacturing-process-overview.md)的 S1—S9 标识。流程模板共享；现状、关系和待办按业务线、环节隔离并在服务端持久保存。编辑业务记录不直接改写知识库文章。

## 首版验收

1. 从平台「大制造」入口进入，能切换内部/外部、三条业务线，打开各环节并返回。
2. 记录现状、添加与完成待办后，刷新和重新登录仍能读取结果。
3. 三条业务线的记录相互独立；改名不丢数据，完成待办不影响现状记录状态。
4. 空白、读取失败、保存失败和权限不足分别显示，失败编辑不丢失。
5. 并发修改能够发现冲突；未授权请求无法读取或修改制造记录。
6. 桌面和手机均能完成选择、编辑、保存与返回的完整路径。开发先验证接口与数据持久化，再做相关组件检查，页面布局与操作由用户最终验收。
7. 供应商、设计方、BOM交接及系统关系可记录并重新读取；参考分工和真实登记明确区分，登记信息不显示成已验证连接。
8. 发布保留现有平台运行配置和其他业务入口，记录平台与制造业务包的准确版本；不使用浏览器代替接口验收。

首版的产品验证重点是：使用者能否在一个环节内留下可信的现状与下一项工作，并在下一次进入时接着推进。
