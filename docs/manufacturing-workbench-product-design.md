版本 v0.6，2026-10-29；全流程候选的本地实现与验收见下节，尚未部署。2026-10-27历史范围：独立管理平台已上线，实际版本与验收范围见[本轮发布记录](release-console-2026-10-27.md)，浏览器视觉验收由用户完成。已上线的工程资料、交接和准备核对设计见[架构产品化设计](superpowers/specs/2026-10-27-manufacturing-architecture-product-design.md)与[发布记录](release-architecture-product-2026-10-27.md)。此前项目管理版发布事实保留为[历史记录](release-product-v2-2026-10-27.md)。

## 全流程候选已实现的边界（2026-10-29）

当前功能分支已完成独立的制造业务工作区，按原[36 场景矩阵](testing/manufacturing-full-workflow-acceptance.md)完成本地隔离 mock 验收；准确逐例版本、首轮失败、修复复跑和回归见[候选证据](testing/manufacturing-full-workflow-results-D4-20261028.md)。这是待集成发布的候选，不能把下文旧项目协同的历史上线事实扩展为全流程已上线。

新工作区以需求与交付评审、订单承诺、固定工程修订、供应计划与合格库存、工单与开工、生产执行、测试放行、分批交付验收、追溯与质量反馈组织真实业务对象。原相机 100 台/60+40、相机 20 台/5+15、打印机 10 台/6+4、OEM 30 台/10+20 的流程已经按完整数量验收。S1—S9 进展由实际业务条件汇总，任务完成和人工阶段标记不能替代业务放行。履约、质量、成本结案分别保留条件、历史结论与当前阻断；RMA/CAPA 能关联实际 ECO 执行及原交付记录。

页面使用具名业务表单、对象详情、服务端动作能力与有界待办导航；授权和状态判定仍在服务端。来源、外部凭据、固定版本、单位精度、物料所有权、客户独立批准/放行、合格质量人员资格都进入真实契约。提交采用操作 UUID 幂等和版本 CAS；冲突保留草稿并要求核对，旧身份会话退役后不能靠陈旧回调继续提交。手册保持一份完整连续正文，进入手册再返回保存项目、阶段和筛选上下文；确认放弃草稿只执行一次离开。

工作流领域数据库与外部 mock 权威状态数据库独立；交换先保存意图，再接收和核对权威回执。超时未知状态通过查询恢复，不能把请求发送当作库存占用、开工或发货成功。新包不会改写已绑定工单、SN、测试限值和旧操作历史；历史来源升级保留原始命令/结果/审计。PF 实际宿主提供企业身份、CSRF、项目/客户范围及当前授权检查。经可信宿主确认的平台所有者和平台管理员默认拥有全部现有及未来制造项目的完整业务权限，包括所有业务角色和检验、处置、质量放行、准备核验资格；无需逐项目授权，也不生成虚假的成员或员工资格记录。普通成员继续按当前项目角色、资格和撤销情况隔离。管理员降权后立即回到普通成员规则；管理查看者、通讯录硬过期只读和 CSRF 限制继续生效。管理员可以发起全部业务动作，真实生产与质量事实、凭据、冻结、前置条件、版本 CAS、幂等及真实操作者审计仍逐项核验。成员名单只展示真实责任配置；分配给其他主体仍需有效项目成员和真实目录姓名，当前管理员可使用隐式自身成员权限，但姓名与有效状态仍由宿主有界查询确认。

旧项目协同及其数据库保留；新工作流数据不冒充或覆盖旧项目。演示/测试数据与模拟连接具有持续可见的标识，只能清理显式拥有的测试数据。旧项目协同详细页面规则保留在下文，具体启用入口依据宿主能力与授权。

当前没有接入真实 ERP/MRP/MES、设备或财务接口，也没有以测试身份代替员工业务验收。外部回执来自有状态 mock 权威边界；成本关闭是登记带签署与内容摘要的模拟 ERP 凭据。组件与实际 HTTP 测试、真实子进程重启、历史版本兼容及独立数据库验证已执行；浏览器视觉、用户多角色操作、真实系统接口、生产业务验收仍单列未执行。下一阶段由发布流程核对准确合并源码、实际隔离运行镜像、Linux 私有测试依赖与证据存储，并在部署后核对真实运行版本。并行编辑的目标架构草稿未自动纳入本轮范围；更广的 ERP/MRP/MES/设备/组织制度需求仍需单独明确和验证。

## 产品定位与设计依据

工作台帮助制造负责人围绕具体制造项目组织交付、分派事项、协调参与方、记录问题并推进阶段。内部自研相机（含数采相机）、3D 打印机和外部 OEM 使用同一管理框架；业务线与责任差异保留在项目中。

首页以正在发生的工作组织。项目、事项、负责人、目标日期、状态和下一步动作是主界面的内容；S1—S9 是项目内部的阶段模板。流程通识和系统解释放在手册，既有流程现状保留为参考。

本设计综合三类已核对的一手产品资料：

- 禅道按项目、任务和看板组织执行，并让用户处理待办、调整状态；借鉴其工作组织方式。[禅道看板](https://www.zentao.net/blog/introduction-zentao-kanban-board-functions-83741.html)、[个人工作区](https://www.zentao.net/book/zentaolite/770.html)。
- ERPNext 将生产计划、BOM、制造工单、工序任务关联；借鉴围绕具体业务单据与操作组织页面。[Work Order](https://docs.frappe.io/erpnext/work-order)、[Job Card](https://docs.frappe.io/erpnext/job-card)。
- Odoo 在制造单详情汇总部件、工序和成本；借鉴一个业务对象汇聚关联工作与信息的方式。[制造单概览](https://www.odoo.com/documentation/19.0/applications/inventory_and_mrp/manufacturing/basic_setup/mo_costs.html)。

业务语义以当前《大制造数字化系统手册》为依据：两类入口的差异贯穿工程、供料、测试和交付，资料版本、物料责任、质量问题和系统数据不能脱离实际项目。此版建立业务协同，不重做 ERP 的库存/财务账、MRP 运算或 MES 设备过站。

## 旧项目协同页面与主路径

`/manufacturing` 在 Agent AppShell 外直接呈现独立管理平台，复用原企业登录、权限探测和私有资源加载。桌面为 232px 左侧业务导航、64px 固定顶栏与全宽业务区；不再显示 Agent 导航或页面内横向主导航。左侧以“奥比大制造”开头，提供工作台、制造项目、事项、系统协同、制造手册，事项计数来自真实未完成事项；支持收起。窄屏改为抽屉，支持遮罩关闭、Escape、焦点约束与关闭后的焦点恢复。

右上角展示当前 Account 的真实姓名、首字头像和平台角色；缺少账号展示信息时只显示“企业账号”。可用的账户动作包含返回 Agent 平台和退出登录，侧栏底部也可返回 Agent 平台。账户动作先经过已有草稿确认，确认放弃后同步清理脏状态及离开守卫，再触发真实路由或退出接口；退出失败保留页面并提示重试，异步提交禁止重复。账号展示信息变更通过可选 `updateUser` 原地刷新，保留草稿与 Markdown 所有权；身份、角色、CSRF 或只读权限变化仍按已有规则退役并重新挂载。通讯录超时只读解释继续可见。

样式限定于制造根节点和壳组件，使用浅灰背景、白色业务面板与蓝色交互主色；无真实功能的搜索、通知或设置不展示。

主路径：新建制造项目 → 确认交付信息 → 进入当前阶段 → 分派任务或确认事项 → 更新资料与协作 → 处理阻塞 → 推进阶段 → 交付结案。手册和流程参考可以随时查阅。

### 工作台

业务区顶部显示当前模块与唯一的“新建项目”入口，顶栏显示模块及当前项目层级。用紧凑数字摘要显示实际在管项目（未归档且未完成）、受阻项目、近七天到期项目和未完成事项，可点击进入相应筛选。

主体左侧展示在推进的制造项目，每个项目展示名称、业务线、当前阶段、负责人、目标日期、完成阶段数和受阻提示，点击进入项目。右侧优先显示阻塞问题、待确认事项和临期工作，提供直接查看/处理入口。底部最近动态来自真实操作。

没有项目时显示真实空状态和明确创建入口，不展示虚构产量、良率、交期率、客户项目或统计；表单提示里的案例必须是明确的示例文本。

### 制造项目

提供列表/看板视图、关键词、内部/外部、业务线及状态筛选。“新建项目”统一使用业务区顶部入口。看板中的每张卡片是一项实际项目，列表中的每一行也对应同一个可操作对象，视图切换保持筛选。

创建时必填项目名、业务线和负责人；产品/型号、客户或接收方、目标交期、计划数量与说明可选。内部项目的客户字段提示为接收方，OEM 提示为委托客户。保存后立即进入项目详情。

项目状态由阶段、事项和显式启用的必需准备核对事实汇总：待启动、进行中、受阻、已完成；全部阶段、事项和当前必需核对均完成才显示已完成，未解决的受阻事项或必需核对缺项优先显示受阻。历史被替代核对保留且不参与当前结论。可归档并查看归档项目，归档不删除记录。旧项目不自动补建新核对要求；项目创建不会把行业参考或业务线调研记录复制为已确认的项目事实。

### 项目详情

顶部展示项目名称、编号、内部/外部与业务线、负责人和交付目标，支持编辑项目资料、归档/恢复。下方用紧凑横向阶段轨道呈现 S1—S9，完成、进行中、受阻和未开始有明确文字与视觉差异。

主工作区聚焦所选阶段，显示阶段负责人、目标日期、当前状态、推进记录。操作包括开始、标记受阻、完成和重新打开；受阻必须填写原因。阶段状态由实际操作者确认，不能由填写说明或完成一条任务自动推进。允许按项目实际情况并行开展不同阶段，不强加未知的公司制度。

阶段下方直接处理该阶段的任务、问题和确认事项：可创建、分派负责人、设置日期/优先级、编辑和流转状态。资料与协作编辑参与方、设计/BOM/测试版本等交接记录及 ERP/MRP/MES 关系。保存冲突时保留草稿并要求核对。右侧或下部显示项目交付资料和操作动态。

手册入口为“了解这个阶段”，按阶段直接打开对应章节；返回时保留项目、阶段、筛选和草稿。旧的业务线流程现状从“流程参考”访问，保留已有数据。

### 事项中心

聚合所有未归档项目的任务、问题和确认事项，可按状态、类型、业务线和关键词筛选。展示所属项目/阶段、负责人、目标日期、优先级和状态，点击打开对应项目并定位。此版负责人是业务责任登记，不意味着给该姓名开通平台访问权限。

### 制造手册

复用平台现有 ArticleMarkdown（含 GFM 表格、代码高亮、Mermaid 和安全链接）及 MermaidDiagram，不新增另一套 Markdown/图表渲染器。手册作为一份完整文档连续展示，能够从头滚动到尾。左侧目录仅用于正文中的标题定位，不切换、截取或重新渲染章节；项目的“了解这个阶段”也只定位到完整正文中的对应标题。图表沿用现有大图体验。

正文唯一来源为 `docs/manufacturing-system-handbook.md`。构建时纳入只读制品并生成准确内容摘要和 Git 更新时间；平台显示实际发布版本的内容，不将编辑中的文件热挂载到生产。更新正文后重新发布制造制品，不在前端复制一份正文。相关流程总览链接通过固定白名单文档打开，不允许任意文件读取。

### 工程资料与版本

在具体项目中建立工程资料包，分别维护 EBOM、MBOM、图纸、SOP、固件、测试程序和限值等资料的来源、编号、修订、责任人和证据。OEM 分别记录客户版本、厂内版本与批准责任。核对完成表示平台内的人工核对，正式外部批准的状态与证据独立保存，未知仍为未知。

资料包经过草稿、提交核对和核对完成；完成后固定内容，新变更建立新修订，旧工单/核对引用保持。资料作废保留原因与原记录，并使受影响的当前准备项重新核对。

### 交接记录

交接绑定资料包的固定修订，各接收方拥有独立记录。可登记交出、接收、退回或撤销；接收要求实际收到的修订与绑定修订匹配，并保存凭据和外部事件时间。平台登记人、登记时间另留审计。页面明确显示“已登记交出/接收”，不发送外部消息、不推断对方系统过账。

### 生产准备

准备核对绑定已冻结资料包、工单/批次依据和计划使用日，在创建时选择本次适用检查项。版本检查在创建时绑定资料明细，后续不能静默换版；物料责任区分自购、客供和混合，设备校准要覆盖使用日期，首件计划与首件通过分开。

每个适用项保留负责人、来源、证据、时间和结论，缺项可创建关联问题。必需项总体结论由服务端计算，任务完成不代替核对。新资料修订通过“替代此核对”建立同执行范围的新核对，保留原必需检查范围，新结论独立形成。旧证据、原始问题和替代事件均可回查。

### 系统协同

维护实际系统/Excel/纸质载体、职责、适用业务线、业务及 IT 负责人和使用现状；按业务线与对象确认唯一有效的数据归属和修改入口。系统停用使相关有效归属失效并留痕，历史引用保持。交换方式为 API 仅是登记，连接状态不作虚假推断。

系统协同提供跨项目交接与待处理项；首页也展示真实待补资料、待回执和准备缺项，点击定位所属项目与对象。后续供应执行、质量追溯、交付和 AI 能力按手册依赖顺序扩展，当前界面仅呈现已实现的操作。

## 数据与交互规则

业务对象为项目、阶段、事项和活动。阶段关联参与方、交接资料与系统关系；项目创建按当时业务线模板保存阶段快照，之后配置改名/停用不能使已存在项目不可读。

阶段与事项分别维护版本，防止两个人互相覆盖。项目和事项创建具备操作 UUID 幂等保护；相同操作标识改变主体、范围或内容时冲突。每次真实变更生成活动；重试不重复生成活动。活动仅显示已发生的操作，不伪造系统同步、审批或生产回执。

“关系登记，尚未验证连接”继续明确展示。没有供应商 API、ERP/MRP/MES 资料及授权前，不调用外部系统，不展示连接成功或实时库存。没有实际审批接口时，人工“确认事项完成”不能标成来自 ERP/MES 的正式审批。

Markdown 文档与企业现状、项目事实分别存储。保留旧 SQLite 表，新增项目表；不删除或覆盖旧现状和任务。生产迁移先一致性备份 SQLite，失败回退保留数据；旧版本可以忽略新增表。

工程资料、系统归属、交接与准备核对使用独立持久化对象，不塞进阶段说明。创建及状态动作具备 UUID 幂等和版本校验，跨对象变更同事务提交。完整业务审计独立保存，页面近期动态截取不删除原始历史。证据引用不触发服务端任意 URL 抓取。

## 产品验收

- 默认首页可新建并推进一个真实项目，不是 S1—S9 链接列表，也不是章节树。
- 一个相机项目和一个 OEM 项目能分别维护交付资料、阶段、任务与协作记录，互不串数据。
- 工作台的待确认/受阻/到期提示来自真实记录，能够点到具体处理位置。
- 完成、阻塞、重新打开、归档/恢复会影响真实状态与活动，重新进入和另一进程读取结果保持。
- 手册通过原有渲染组件展示，实际正文全部章节可读，Mermaid 语法可解析，阶段定位和返回保持工作上下文。
- 旧流程现状可查；401/403、CSRF/Origin、hard-stale 只读、私有缓存及资源版本校验保持。
- 工程侧负责接口、组件、构建、隔离候选和生产边界；浏览器视觉验收依现有约定由用户完成。

## 全分支审查修正的候选行为（尚未部署）

工程与工单工作区提供“确认修订合同条件”：选择固定客户版/厂内版，登记客户签署人、协议凭据和明确的批准、放行、验收及物料责任条件。原始合同和旧工单/SN/放行不改写；新协议只适用选定修订，既有修订的已知条件不能用补充确认降低，未知条件可继续确认。客户工程批准、MES 交接、当前物料与新工单准备仍分别核验。交付按实物修订适用条件判断，部分验收不能推断具体哪些 SN 已验收。

CAPA 验证失败后可在同一开放 CAPA 追加修订调查和纠正措施；所有失败历史保留，新措施必须有对应的新效果验证才能关闭。界面显示当前纠正依据及每次验证依据。固定初始路线和质量批准返工路线可明确声明“不消耗新增物料”的校准、测试或调整工序；真实执行允许空用料，不再要求虚构库存消耗，要求用料的工序仍必须提供实际证据。

物料需求列表与详情对待冻结、已冻结和未确认解冻使用相同的阻断依据。供应计划可分页选择第50条以后的工单，切换项目不会带入旧选择或迟到回调。成员授权的接受版本进入当前项目的新鲜度下界；停用账号的历史授权仍可撤销。退出登录失败保留可继续使用的工作区并提示重试，成功退出或真实身份失效立即退役旧会话。

客户放行按实际勾选 SN 的同一固定修订读取适用协议，显示并提交对应客户版本；原始 C1 合同不会覆盖已确认的 C2 放行范围。核对中、读取失败、缺失修订或混合修订时不能保存。选择变化保留正在填写的客户签署人和凭据，迟到资料不能覆盖新选择；切换项目退役旧草稿。
