## 验证中发现的问题与处理

- 独立 E30 测试需要其专用宿主环境，沿用现有通用前端与 E30 分开运行的规则，未增加跳过或放宽断言。
- 旧 HTTP 表单测试在初始请求完成前清空选择框，随后被初始化选择覆盖。保留失败装置并记录请求完成时序后，将该处固定等待改为等待实际加载完成；原「清空后客户放行」断言和业务事实校验保留。
- 本地联调装置首次使用 HTTP Origin，被宿主正式 HTTPS Origin 约束拒绝 403。改为临时证书校验的本地 HTTPS 服务后验证通过，未修改产品鉴权规则。
- 目录/日志源 ID 和游标按十进制字符串传输；内部及快照原始整数保留精度。快照再次截断时按最终保留数据重算 MySQL 续查边界，QuestDB 不生成未验证的续查键。
- 日志索引的时间样本为整数毫秒，查询边界使用精确整数运算，保留微秒输入的半开区间语义。
- 新测试目录与原有 `tests/test_api.py` 重名，触发全量收集冲突。通过测试目录包隔离及相对导入解决，未删除测试、修改导入模式或放宽断言。
