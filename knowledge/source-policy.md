# 知识来源与维护规则

本知识库以公开资料、独立解释和明确标注的教学示例构成。目的在于帮助接手制造信息化的负责人学习和调研。公共知识不代表公司当前流程、系统或成熟度。初次整理日期：2026-10-27。

## 区分四类内容

| 类型 | 如何表述 | 可以支持的结论 |
| --- | --- | --- |
| 可核查公开事实 | 写明发布者、对象、日期和原始出处 | 来源实际披露或说明的范围 |
| 厂商或企业自述 | 使用“官方文档说明”“企业披露”“案例称”等措辞 | 产品文档范围或被披露案例本身 |
| 综合分析与实务建议 | 标明适用条件，并解释判断依据 | 供访谈、设计或决策讨论，非已验证公司事实 |
| 教学假设与计算 | 明确假设、输入、单位、范围和步骤 | 例子内部的解释及算术，不是实际业务数据 |

技术定义优先使用标准制定组织、研究机构、行业组织和产品官方文档。案例优先使用公司原始披露、官方帮助及公开机构报告。新闻与转述可用于发现线索，不替代可以取得的原始材料。

## 记录来源的最小信息

来源记录使用 JSON 保存：`id`、`title`、`publisher`、`url`、`access_date`、`published_date`、`source_kind`、`evidence_scope`、`limitations`、`topics`。发布日期不明时用 `null`，不从搜索引擎的抓取时间推定首次发布日期。正文引用直接链接到支持该段内容的页面。

同一 URL 可能因独立专题引用拥有多个来源编号。总索引按 URL 归并，保留编号别名和对应文章。唯一来源数按归并后的 URL 统计，不能通过更换编号重复计数。

若来源只能读取公开摘要、目录或官方搜索索引，应在来源记录中明确。目录只能支持标准名称、状态等目录事实；摘要只能支持摘要陈述，不能写成已核读全文。抓取失败时，不猜测内部内容，也不把同名的第三方文档当成原文。

## 使用案例数字

每项数字保留企业或工厂、统计期间、指标名称、单位、比较基线及发布者。企业披露和机构发布不自动等于知识库完成独立审计。两处披露冲突时追查口径；无法解释的数字不进入学习结论，不以较大数字替换较小数字。

产品页面和接口说明可能持续更新。记录核验日期，并在用于采购、对接或项目立项时重新确认实际版本、授权、适用组织与服务边界。公开存在接口说明不代表本公司的账号已经获准调用。

## 补充公司专属资料

公司专属条目另行注明资料提供角色、确认日期、对象范围和内部证据位置。流程现状、问题假设、拟议方案和已验收结果分别记录。对“IT 部已采购 MRP”的后续整理，先确认产品身份与使用范围，再补具体操作和接口说明。

更新文章时核对受影响术语、交叉链接、示例和来源。发现原解释失效，应修正对应结论，并在变化记录中说明原因。知识库当前为仓库内的阅读与调研资料；接入平台阅读、搜索或 Agent 检索属于后续应用工作。

## 本版资料状态

正文主要采用自行归纳的解释、短引用和原始来源链接，不整批复制网站或付费标准全文。来源登记保留访问和证据范围，以便读者回到原始材料继续阅读。结构化目录是内容清单，不表示已经构建检索服务或完成平台上线。
