# 制造信息化接手调研与访谈问题

适用读者：刚开始负责制造信息化，需要与业务、IT、工厂和供应商建立共同语言的负责人。整理日期：2026-10-27。本文提供调研方法和问题模板，不描述公司现状。

接手工作的第一项产出，是解释清楚一笔真实业务如何从需求走到交付、在哪里等待、谁决定下一步、哪些数据值得相信。系统名称只是入口。访谈时选一笔近期订单、一批在制品和一笔真实异常，让当事人用原始单据和记录带你走完整条链路。

## 用同一条业务链访谈不同部门

每个问题都尽量追到四类证据：业务对象及编号、状态变化及时间、执行与审批责任、所在系统及原始记录。如果只能得到口头结论，就在调研记录中标为“受访者陈述，待记录核对”。同一问题得到不同答案时，保留差异并回到具体订单核对。

| 对象 | 核心问题 | 希望看到的材料 |
| --- | --- | --- |
| 经营与制造负责人 | 当前交付、库存、质量、成本中最影响经营的三件事是什么？改善以什么数据验收？ | 经营例会问题、订单履约记录、指标定义 |
| 销售与订单管理 | 客户要货日和公司承诺日各由谁维护？改期和插单如何传到计划？ | 订单原始版本、变更记录、交期确认 |
| 计划与 PMC | 生产计划怎么生成？缺料与产能冲突如何处理？谁能调整优先级？ | 主计划、排产表、缺料表、异常清单 |
| 采购与供应商管理 | 采购建议何时成为采购订单？交期由谁确认？替代料谁批准？ | 采购申请、采购订单、供应商回复、催料记录 |
| 研发与产品工程 | 哪个版本允许生产？BOM、图纸、固件和测试规范如何一起生效？ | 已发布版本、变更单、试产问题记录 |
| 工艺与制造工程 | 工序、工时、工装、程序和作业指导如何下发？现场如何确认适用版本？ | 工艺路线、作业指导书、程序发布与签收 |
| 生产主管与操作人员 | 今天做什么从哪里看？领料、报工、返工和停机怎样记录？ | 现场工单、过站记录、交接班记录 |
| 质量与可靠性 | 什么条件触发隔离、复检或放行？缺陷怎样关联供应批次和出货产品？ | 检验记录、不合格单、处置记录、客诉闭环 |
| 仓储与物流 | 库存是否区分可用、待检、冻结和在途？盘点差异怎样处置？ | 库位台账、批次记录、收发单、盘点差异 |
| 设备与测试维护 | 故障、校准、程序变更和维护是否影响产品放行？谁维护设备能力？ | 维护记录、校准记录、测试程序版本 |
| 财务与成本核算 | 实物移动如何对应核算记录？月结差异主要出在哪些交接处？ | 核算口径、工单结算差异、库存对账记录 |
| IT 与实施服务商 | 当前系统范围、实际使用范围和采购合同范围是否一致？接口故障谁负责？ | 合同功能范围、架构、接口台账、工单记录 |

## 六组必须问透的问题

### 订单与计划

1. 需求来自正式订单、预测、备货还是样品？它们是否有不同的批准规则？
2. 客户需求和预测同时存在时怎样处理，如何避免重复计算？
3. 客户原始要求、确认承诺和内部计划是否分别留痕？
4. 订单改期、取消和数量变化之后，已发出的采购与生产任务如何处置？
5. 计划冻结范围由谁确定，临时插单能改变哪些已经承诺的任务？
6. 一次缺料是按订单、产品、工单还是物料统计，能否解释到原始需求？
7. 哪些工序或设备限制了交付，计划中如何体现换型、维护和人员技能？
8. 工单完成但无法出货时，通常卡在什么状态，由谁解除？

### 物料与工程数据

9. 物料编码由谁创建，如何识别重复编码和一物多码？
10. 采购单位、库存单位和生产用量单位如何换算，精度由谁定义？
11. BOM 中的用量、损耗、替代关系和适用范围由谁负责？
12. 研发 BOM 与生产 BOM 如何转换和批准，转换差异留在哪里？
13. 工程变更按日期、工单、批次、序列号还是其他条件生效？
14. 在途物料、库存旧料和在制品遇到变更时由谁决定消耗、返工或报废？
15. 供应商制造商料号与内部编码之间能否准确对应？
16. BOM、图纸、工艺、固件和测试程序是否可能处于不一致版本？

### 采购与库存

17. 采购提前期、最小采购量和包装倍量来自哪里，多久复核？
18. 供应商承诺与系统需求不一致时，谁决定追料、换料或调整生产？
19. 到货、收货、检验合格和上架是否为不同时间点？
20. MRP 是否会把待检、冻结、客户专用或失效库存当作可用？
21. 物料已经到厂但系统仍显示缺料时，哪一步尚未完成？
22. 供应商寄售、委外在途、线边库存和退料由哪些台账管理？
23. 盘点差异的数量、原因和批准如何记录，如何防止反复出现？
24. 关键长周期物料的供应风险是否有人定期核查？

### 现场执行与质量

25. 工单、批次和序列号分别在哪个环节生成？
26. 首件确认、工艺检查和测试放行由什么条件触发？
27. 实际耗料如何形成，扫码、人工录入和倒冲各适用于什么环节？
28. 替代料临时使用是否保留批准人、适用对象和有效期？
29. 不合格品能否被下一工序领用，系统与现场如何共同控制？
30. 返工是否有独立工艺和复测记录，是否影响一次通过率统计？
31. 设备离线、扫码漏录、换班和跨天时，记录如何补全并区分发生与补录时间？
32. 测试结果能否关联测试程序、工装、设备及校准状态？
33. 客诉的一台产品能否追到关键部件、加工、测试和出货记录？
34. 一批来料出现问题时，能否查到所有受影响在制品和已出货产品？

### 系统与数据

35. 业务人员实际每天使用哪些软件、Excel、共享文件和聊天群？
36. 同一字段在多个系统不一致时，哪一处有权修正？
37. 数据是实时、定时还是手工导入，页面显示的更新时间是什么？
38. 接口失败会怎样被发现，谁修复，如何证明没有遗漏和重复？
39. 账号离职、调岗、供应商访问和临时权限由谁维护？
40. 系统备份后是否验证过恢复，恢复后如何核对业务完整性？
41. 软件升级、基础数据变化和接口调整是否有对应的回归业务样本？
42. 现场断网后允许继续哪些作业，恢复连接后怎样对账？

### 项目与组织

43. 已采购系统的合同模块、验收状态和当前使用范围分别是什么？
44. 系统难用是流程未定义、数据不准、功能缺失、培训不足还是性能故障？有哪些具体证据？
45. 每条关键流程有没有业务负责人，争议谁裁定？
46. 当前需求是否能关联原始业务问题、责任人和验收标准？
47. 服务商承诺的收益使用什么基线、统计周期和适用范围？
48. 关键用户是否有时间参与数据清理、演练与验收？
49. 新流程上线后哪些旧表格、旧入口和重复录入可以正式退出？
50. 出现重大差异时，停止上线、恢复作业和保留记录分别由谁负责？

## 用一次现场观察验证访谈

跟一笔实际业务走，不只听部门介绍。记下产品和订单编号，从计划指令到领料、加工、检验和入库，观察实物流与记录流是否同时发生；记录等待、搬运、重复输入和人工判断的位置。价值流图可以同时呈现物料与信息流，并从现状推导目标流程；这里用它组织观察，而不是先设定一张漂亮的目标架构。[R06 Lean Enterprise Institute](https://www.lean.org/lexicon-terms/value-stream-mapping/)

现场记录建议包含：观察时间、对象编号、工序或地点、当前状态、等待原因、输入材料、产生记录、责任角色、数据所在位置、待确认事项和后续核对结果。先用少量真实样本找出链路，再决定是否扩大抽样。

## 第一轮调研的交付物

形成五份可讨论的事实材料：业务流程现状图、系统与数据台账、关键问题及证据表、已采购系统使用情况表、待确认事项清单。每个问题至少能够回答“谁受到影响、影响什么业务、证据在哪里、谁能够确认”。改善项目的优先级在这些材料基础上讨论，见[现状评估与建设路线](../03-implementation/01-assessment-and-roadmap.md)。
