# 制造信息化标准与一手资料阅读指南

整理日期：2026-10-27。标准、行业方法、厂商文档与企业案例回答不同问题。阅读时先确定目的：需要理解业务、设计系统边界、定义数据、评价能力，还是查产品的具体操作。以下为阅读用途说明，不代替标准全文或产品实施手册。

## 如何选择材料

| 资料类型 | 适合回答的问题 | 阅读时要保留的边界 |
| --- | --- | --- |
| 政府场景指引 | 制造数字化有哪些典型业务场景 | 场景目录不等于企业项目优先级 |
| 国家或国际标准 | 术语、架构、能力与接口如何形成共同语言 | 先核对版本、范围与可取得的正文 |
| 行业组织方法 | 供应链、质量和精益如何组织流程 | 行业适用条件与实施约定仍需确认 |
| 厂商产品文档 | 某产品具体怎样建模和操作 | 产品功能不能代表所有系统的统一要求 |
| 企业公开案例 | 某工厂在特定条件下如何处理问题 | 自述成果与可复制条件需要分开 |
| 企业内部记录 | 我们现在怎样做、问题在哪里 | 以授权取得的真实业务证据为准 |

## 中国智能制造资料

[R01 工信部 2025 年版典型场景通知](https://www.miit.gov.cn/jgsj/zbys/wjfb/art/2025/art_3033120c7e8d4e4aba0bf76b44bcc645.html)可作为定位业务场景的官方入口。通知成文于 2025-04-19、发布于 2025-04-27，并附参考指引。检索时要区分正式版与征求意见稿；本条已核查通知正文，未将附件内容当作已逐条核读的要求。

[R02 GB/T 39116-2020 官方目录](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=809991917D73FE52B65C1ECC8B51B418)显示《智能制造能力成熟度模型》的标准名称、发布日期、实施日期及检索时的状态。当前阅读只核查目录元数据，不据此声称已完成标准符合性评价，也不从目录推演具体等级条款。

使用成熟度框架时，可先讨论组织、流程、数据和技术能力在哪些环节不足，再考虑是否需要正式评估。系统数量、设备联网数量和大屏数量都不能单独说明一条业务链已经具备稳定能力。这是本知识库的管理建议，正式评价应采用适用标准和规定的方法。

## 系统架构与互联

ISA-95 适合学习企业计划与制造运营之间的业务活动、对象及接口关系；OPC UA 适合继续理解工业互操作；NIST 的制造数字线程和 OT 安全材料适合补充生命周期数据连接与运行环境约束。具体已核读来源收录在[来源索引](../sources/README.md)，系统概念见[系统全景](../02-systems/01-system-landscape.md)。

阅读这些材料时，不要把逻辑分层直接当作部署拓扑，也不要从某个协议支持“安全连接”推断整个工厂的权限与网络已经安全。需要继续核对身份、对象模型、版本、运行边界和维护责任。

## 质量 精益与电子制造

| 入口 | 优先学习内容 | 继续阅读的条件 |
| --- | --- | --- |
| [AIAG Quality Core Tools](https://www.aiag.org/expertise-areas/quality/quality-core-tools) | 产品质量策划、风险、控制与测量的关系 | 需要使用具体方法时，核对手册版本、客户要求与授权 |
| [NIST 过程能力](https://www.itl.nist.gov/div898/handbook/pmc/section1/pmc16.htm) | 能力指标、分布及过程前提 | 先有稳定且适用的数据，再解释指标 |
| [NIST 接收抽样](https://www.itl.nist.gov/div898/handbook/pmc/section2/pmc21.htm) | 批接收决策和过程质量的区别 | 具体方案由质量职责确定 |
| [Lean 价值流图](https://www.lean.org/lexicon-terms/value-stream-mapping/) | 物料流、信息流、现状与目标流程 | 先观察实际业务，再讨论改进 |
| [Lean 需求节拍](https://www.lean.org/lexicon-terms/takt-time/) | 客户需求与可用时间的关系 | 明确产品族、时间范围和单位 |
| [IPC-A-610 官方介绍](https://www.ipc.org.cn/standards/ipc-a-610) | 电子组件可接受性标准的用途 | 具体验收条件以适用版本正文为准 |

这些入口的用途在[质量与测试数据](04-quality-lean-and-test-data.md)中结合制造系统作了说明。公开介绍适合建立知识地图，不能替代需要按条款执行的专业作业文件。

## 企业案例怎么读

先看业务对象和生产模式，再看数字化动作，最后看成果的统计条件。对嘉立创，可以研究产品数据如何进入报价、下单和生产协同；对海尔，可研究多样化需求与工厂协同；对三一，可研究复杂装备工厂的现场问题；对施耐德，可研究具体工厂的运营改善。各案例之间的差异见[比较与迁移](../04-cases/05-comparison-and-transfer.md)。

对任何量化成果，保留工厂、时间段、统计口径和发布者身份。两个来源数字不一致时，不应选择更漂亮的一项；应查差异，查不清就保留为未解决问题或不用于结论。
