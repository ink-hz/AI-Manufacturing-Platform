## Reasoning and rejected approaches

1. Existing MF `PrivateRoute` authorizes globally through old callback, and PF both central authorization and shell function restrict owner/admin. Simply adding project roles beneath that router leaves employees unable to reach the feature; loosening the callback would expose old projects. New exported `WORKFLOW_API_VERSION=1`/`build_workflow_router` and exact `/workflow` routes solve both. Original router and callback unchanged; new router is mounted before old catchall. Separate exact central whitelist, separate shell handler, explicit CSP asset source, member bootstrap and no legacy member fetch are all planned.
2. New probe must not accidentally disable old UI. Intentional absent workflow config or an old library returns200 legacy-only bootstrap, nullable dataset and workflow_available=false. Configured storage corruption returns503 visibly. Truly older PF without new route can return404 and frontend fallback to old probe. Four source/config combinations have tests.
3. Identity comes only from AuthContext. Subject grants validate live trusted control user records. Display names/front-end role/body/header/synthetic customer identity confer nothing. Global management_viewer remains read-only even with grant. Admin config privilege does not auto-grant quality decision qualification; qualification grants are explicit/audited and rechecked each request.
4. Independent new domain tables avoid stuffing business into old project JSON, writing existing seven projects or coupling new members to legacy scope. Existing PackageItem/calendar/instant validators are reused; small pure validation helpers may be extracted without changing legacy behavior. Existing old phase/manual-readiness composition is deliberately not reused as authority for new actual stock, first article or releases. This is semantic reuse with separate aggregate boundaries, not copying another ERP engine.
5. Single project CAS serializes cross-object business mutations and prevents ambiguous quantity races. UUID replay checks canonical request payload and current authorization before returning prior result. Normalized quantity/link/source/version columns and immutable typed events support real queries and persistence; unrestricted JSON bags or a generic phase-complete scaffold are excluded.
6. Two SQLite stores cannot share an atomic business transaction. Durable main-domain pending outbox precedes authority transaction; receipt apply is independent. Timeout/crash leaves unknown/pending, receipt query precedes any retry. Mock authority owns actual stock/reservations/shipped SNs/sequence and performs atomic concurrent balance checks. The platform cannot manufacture accepted reservations from local plan allocations.
7. Inbound facts need an explicit authoritative path too: source.pull fetches configured adapter records, including external receipt/IQC/customer events. Manual supply entries never alter authoritative inventory. External test setup may create simulated external events, after which normal authorized API pulls/validates/persists them. No scenario inserts business success into domain tables. Imports follow same validators and are file-labeled, not silently promoted to authoritative posting.
8. Trial and bulk are distinct scoped authorizations sharing one quantity budget. Trial needs correct version/equipment/people/customer and its own plan-supplied material quantities, not a first article result or the entire bulk kit. Bulk requires genuine successful first article on matching revision/test/calibration scope. Requirement.execution_scope is supplied by authoritative plan, avoiding local MRP expansion.
9. Fixed revisions, old WIP, stock/PO impacts and actual switch receipts prevent silent ECO replacement. Partial old workorder cannot be rebound wholesale; remaining unexecuted scope must move explicitly with quantity-preserving allocation transfer. Requested freeze locally blocks new shipments while confirmed external state remains separate; unconfirmed unfreeze cannot reopen shipping.
10. Quality needs finite measurements and versioned limits; original failed attempts remain. Independent manufacturing/quality/customer release rows are per-unit. Shipped/signed/accepted quantities and fulfillment/quality/cost closures remain separate. RMA/CAPA closes only after effective corrective action; ECO execution is required when the action is engineering, not for unrelated verified supplier/training actions. E24 deliberately exercises ECO.
11. Complete practical UI is distributed across A4/B/C and integrated D1, so earlier domains have usable forms rather than backend-only endpoints. Dedicated named forms, authorized object pickers, quantity/version/source/history, daily exceptions and drilldowns replace raw JSON editors/wizard lists. Existing dirty/handbook/account shell behavior stays the owner of navigation safety.
12. Acceptance is bounded15 reviewable tasks plus36 cases. Four full flows begin with demand, include split quantities and feedback, and stop at first failure. Exception cases use declared API-built preconditions. Evidence records both source commits, run/seed/clock, trusted identity boundary, all object/operation IDs, read-only DB snapshots, mock receipts, first failure and elapsed time. Alternate seeds, process kills and malicious identities test actual behavior, not a status bit.
